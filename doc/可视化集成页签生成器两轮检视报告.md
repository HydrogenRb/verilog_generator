# 可视化集成页签生成器两轮检视报告

## 结论

`appendix/run_designer.py` 已完成第一版离线交付。它复用主解析器，不修改 module 页签，有 error 时阻止导出，且只在临时工作簿通过主生成器 check 后原子发布。

## 第一轮：功能与安全检视

- 导入：支持中文/空格路径，列出所有 module 候选和解析诊断，必须显式选择三个不同角色。
- 画布：三列模块卡片、按分类/方向/位宽显示端口、拖拽/键盘点选连线、SVG 网络线、搜索和方向过滤。
- 大模块：端口 DOM 使用固定行高虚拟窗口，每卡最多渲染 70 行。合成 3000 端口的建议索引回归在 5 s 上限内完成。
- 建议：名称/模板 provenance 索引产生确定性候选，每条显示方向、名称、形状、分类的得分原因；位宽差异不自动批量接受。
- 全局规则：缺失端点、重复 input、同 module 多端点、方向/interface 冲突、多 output 为阻断 error；定宽差异、无驱动和未确认端口分类呈现。
- 工程：`.xvlink.json` 持久化、SHA-256 源指纹、失效 ID 保留、100 步撤销/重做。
- 导出安全：默认禁止覆盖源 XLSX；同目录临时文件、主生成器 check、`os.replace` 原子发布；服务只绑定回环地址。

第一轮审查过程中修正了建议算法的平方级全端口扫描，改为名称/模板索引后只计算可解释候选；同时修正 TOP output 在 GUI 驱动数统计中被错当内部 driver 的问题。

## 第二轮：导出不变性与端到端回归

- 使用 `09_version_2/test.xlsx` 构建无连接工程、确认全部子模块端口、导出到中文加空格的路径：通过。
- 导出文件由 `parse_workbook()` 重新读取并识别 TOP 及两个子模块：通过。
- 原工作簿三个 module worksheet XML 与导出后逐字节相同：通过。
- 默认覆盖源 XLSX 的调用被明确拒绝：通过。
- 多驱动项目在导出前产生 `MULTI_DRIVER` error：通过。
- 静态资产不含 `https://` 远程依赖，Python/JavaScript 语法检查：通过。

已知限制已在 `appendix/README.md` 显式记录：第一版只处理 TOP + 两子模块；同一网络在每个 module 内只能有一个端点；新集成页不复制主题样式。
