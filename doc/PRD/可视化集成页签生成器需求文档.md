# 可视化集成页签生成器需求文档

## 1. 文档目的

本文档供后续开发 Agent 实现一个独立的新软件。该软件读取三个符合当前项目 specification 的 module 页签，让用户通过类似“拉线游戏”的可视化界面建立端口连接，最终输出可被现有 `xlsx2verilog.py` 直接读取的集成页签。

本文档中的“必须”属于验收条件，“应当”属于默认实现要求，“可以”属于增强项。若实现过程中需要改变集成页签格式，必须先同步修改本项目 README、生成器和回归测试；第一版不得自行扩展格式。

## 2. 产品目标

### 2.1 核心目标

1. 输入一个包含三个 module 定义页签的 XLSX。
2. 让用户指定一个 TOP 和两个子模块。
3. 自动分析端口，给出可信的连接建议。
4. 用户可在画布上拖拽连线、断线、批量接受建议并处理未连接端口。
5. 实时显示方向、位宽、interface、模板展开和多驱动问题。
6. 输出一个符合当前项目规则的集成页签，并保留三个原始 module 页签。
7. 输出 XLSX 必须能够通过：

   ```powershell
   python .\xlsx2verilog.py .\输出文件.xlsx --check
   ```

### 2.2 非目标

- 不生成 mux、仲裁器、寄存器、CDC、协议转换或其他功能 RTL。
- 不推断同名信号一定可以安全连接；自动结果始终是建议，最终由用户确认。
- 不支持一个文件中多级层次结构的一次性展开；第一版只处理一个 TOP 加两个直接子模块。
- 不修改 module 页签中的端口、位宽、方向或分类数据。
- 不替代综合、lint、仿真和 CDC 工具。

## 3. 术语

- **模块页签**：包含 `端口名`、`位宽`、`数值`、`i/o` 等表头的页签。
- **集成页签**：描述 TOP/子模块连接、子模块间连接和未连接端口的页签。
- **端点**：画布上一个可被连线连接的 module port。
- **网络（net）**：一组应连接到同一 Verilog 信号的端点。
- **建议连接**：软件根据名称、方向、位宽等生成、尚未经用户确认的连接。
- **已确认连接**：用户确认并将写入集成页签的连接。

## 4. 输入要求

### 4.1 文件与页签

- 必须支持 `.xlsx`。
- 默认输入为一个工作簿中的三个 module 页签；工作簿可包含其他说明页签。
- 软件必须列出识别到的 module 名称和来源页签，让用户选择 TOP、子模块 A、子模块 B。
- module 名称解析必须与当前生成器一致，支持 `RISCV_CORE`、`module:RISCV_CORE` 和 `module：RISCV_CORE`。
- 表头、方向、位宽、数组、interface、命名模板、`修改/修改列`忽略规则必须遵循本项目 README。
- 若文件中不是恰好三个可用 module，软件不得静默猜测；应让用户明确选择三个，或阻止继续并说明原因。

### 4.2 输入保护

- 不得覆盖用户选择的源文件，除非用户在最终确认框中明确选择“覆盖原文件”。
- 默认使用“另存为”。
- 输出必须保留未选页签、单元格内容、合并单元格及 module 页签的主要格式。
- 若存在同名集成页签，应提供“替换集成页签”“另存新文件”“取消”三种选择。

## 5. 用户流程

### 5.1 导入与预检查

1. 用户选择 XLSX。
2. 软件显示解析进度。
3. 软件展示 module 候选、端口数量、解析 warning/error。
4. 有阻断性错误时禁止进入连线画布，并提供页签、行、列和修复建议。
5. 用户指定 TOP、子模块 A、子模块 B 后进入画布。

### 5.2 可视化画布

- 默认三列布局：左侧 TOP，中间子模块 A，右侧子模块 B；允许交换两个子模块位置。
- 每个模块以卡片显示，端口按分类折叠/展开。
- 端口至少显示：名称、方向、packed 位宽、unpacked 数组、interface 类型、模板来源、条件宏。
- input、output、inout、interface 使用不同颜色和图标，颜色不能是唯一识别手段。
- 用户从一个端点拖到另一个端点创建连接；拖动过程中高亮合法候选，禁用确定非法的候选。
- 点击已有连线可显示所有端点、驱动端、位宽与诊断；支持 Delete/Backspace 删除。
- 支持框选、多选、批量连接、撤销、重做、缩放、平移、搜索和按分类过滤。
- 大模块必须支持端口虚拟滚动，不得一次渲染所有不可见节点造成明显卡顿。

### 5.3 自动连接

- 提供“生成建议”按钮，不得在用户未确认时直接落盘。
- 建议按置信度分为高、中、低三级。
- 用户可以逐条接受、拒绝，也可以批量接受所有高置信度建议。
- 接受建议后立即重新运行全局校验，避免局部合法但整体多驱动。
- 自动连接必须可重复执行，并且不会重新创建已拒绝且输入数据未变化的建议。

### 5.4 未连接端口

- 所有未进入网络的子模块端口进入“未连接端口”面板。
- 软件必须明确预览生成语义：input 接零，output/inout 空连接，interface 空连接。
- 用户可把端口标记为“确认未连接”；未确认的未连接端口在导出前产生 warning，但可由用户选择继续。
- TOP output 若没有子模块 output/inout 驱动，将由当前生成器在 TOP 内 assign 为零；连接到该 TOP output 的子模块 input 使用同一置零信号。

### 5.5 导出

1. 用户点击“预览集成页签”。
2. 软件显示二维表格预览和所有 warning/error。
3. 有 error 时禁止导出；warning 需要用户确认。
4. 导出到临时文件后调用当前生成器的校验能力。
5. 校验通过后原子替换目标文件；失败时保留临时诊断，不破坏已有输出。

## 6. 连接语义

### 6.1 TOP 与子模块

- TOP input 可以连接一个或多个子模块 input。
- TOP output 可以由一个子模块 output/inout 驱动。
- TOP output 也可以连接一个或多个子模块 input；没有 output/inout 驱动时，当前生成器会将其 assign 为零。
- TOP input 与子模块 output 直接连接属于方向冲突，必须阻止或要求用户明确修改 XLSX 方向。
- 多个子模块 output 同时驱动一个 TOP output 至少是 warning；默认阻止导出，除非项目设置允许多驱动并要求用户二次确认。

### 6.2 子模块之间

- 普通网络默认必须恰好有一个 output 驱动端，可以有一个或多个 input 接收端。
- 没有 output 的普通网络为 warning；多个 output 为 error。
- inout 网络必须单独标识，不能套用普通单驱动规则。
- interface 只能与相同基础 interface 类型连接，不能与普通 wire 端口直接连接。

### 6.3 位宽与形状

- packed 维度和全部 unpacked 维度相同为精确匹配。
- 默认值相同但符号名不同为中置信度建议，并显示“符号不同、有效宽度相同”。
- 宽度或数组形状不同必须显示醒目 warning；默认不自动接受。
- 不确定宽度 `114` 必须显示为待确认状态，不能视为普通精确匹配。

### 6.4 模板与条件分类

- 模板端口按来源模板和展开值匹配，不能用宽泛前缀匹配普通端口。
- `{a,b}` 与 `{b,a}` 应按展开值对应，不按页签行序对应。
- 条件分类端口必须保留条件宏元数据；连接条件不同的端口时提示用户可能产生编译配置缺口。

## 7. 自动匹配评分

建议采用可解释的加权评分，每条建议必须能展开显示得分原因：

| 因素 | 建议权重 |
|---|---:|
| 端口名完全相同 | +100 |
| 去除常见前后缀后相同 | +50 |
| 模板来源与展开值相同 | +100 |
| 方向组合合法 | +40 |
| packed/unpacked 形状完全相同 | +40 |
| interface 基础类型相同 | +60 |
| 分类相同或语义接近 | +10 |
| 宽度不一致 | -80 |
| 方向确定冲突 | 禁止 |
| interface 与普通端口混连 | 禁止 |

常见前后缀列表必须配置化，默认只包含大小写和分隔符归一化，不应擅自删除业务含义字符。

## 8. 集成页签输出格式

### 8.1 总体结构

- 第一连续区：TOP 位于第一组，两个子模块随后；同一行表示 TOP 与一个或两个子模块的连接。
- 后续多模块连续区：子模块之间的内部网络。
- 后续单模块区：该模块确认未连接的端口。
- 每个模块块使用相邻的 `端口名`、`i/o` 两列。
- 不同连接区之间至少保留一个空列。
- 模块名写在 `端口名` 表头上方同一列，默认输出直接名称，不添加 `module:` 前缀。

### 8.2 行生成规则

- 一个网络对应一行；连接多个接收端时在同一行的相应模块列填入端口。
- 模板两端可安全批量表达且展开集合完全一致时，可以保留 `{{变量}}` 模板写法；否则必须输出逐个展开后的物理端口行。
- `i/o` 必须来自 module 定义，不能根据画布方向重新猜测。
- 不得向 `修改/修改列` 写入任何控制数据；这类列会被当前生成器忽略。

### 8.3 可追踪性

- 输出页签可以在不影响解析的备注区写入生成器版本、生成时间、源页签名称和连接项目 ID。
- 每个导出网络应在软件项目文件中具有稳定 UUID；XLSX 第一版不要求写入 UUID。

## 9. 校验与诊断

- 每条诊断包含：级别、模块、端口、源页签、源行、网络 ID、原因和建议动作。
- error 与 warning 必须分开展示并可按模块过滤。
- 双击诊断应定位并高亮相关端点和连线。
- 导出前至少检查：缺失端口、重复连接、方向冲突、多驱动、无驱动、位宽/数组不一致、interface 混连、模板集合不一致、条件宏不一致、未确认未连接端口。
- 必须展示当前 `xlsx2verilog.py --check` 的原始诊断，不能只显示 GUI 自己的解释。

## 10. 项目保存与恢复

- GUI 工程状态保存为独立项目文件，建议扩展名 `.xvlink.json`。
- 项目文件至少保存源 XLSX 路径与指纹、三个角色、画布布局、网络、已拒绝建议、未连接确认和软件版本。
- 重新打开时校验源 XLSX 指纹；源文件改变后执行差异迁移，按稳定的 `module + port + template value` 标识恢复连接。
- 无法恢复的连接进入“待修复”，不得静默删除。
- 撤销/重做至少保留最近 100 个操作。

## 11. 架构要求

- 解析层、连接模型、规则校验、XLSX 输出和 UI 必须分层，业务规则不得写死在拖拽事件中。
- 当前项目的 XLSX 规则应抽取为可测试的共享模块或通过稳定接口复用，避免 GUI 与 `xlsx2verilog.py` 两套规则漂移。
- 自动匹配器只产生建议，不直接修改已确认网络。
- XLSX 写入采用临时文件加原子替换。
- 新软件可以使用可离线打包的 GUI/XLSX 依赖，但运行时不得依赖互联网、云账号或远程服务。
- Windows 为第一验收平台；路径必须支持中文、空格和长文件名。

## 12. 非功能需求

- 三个模块合计 3000 个端口时，初次解析目标不超过 5 秒，普通拖拽反馈目标低于 100 ms。
- 自动建议计算必须可取消，并显示进度。
- 软件崩溃后应能从自动保存恢复最近状态。
- 日志不得记录工作簿完整内容；默认只记录结构化诊断和散列后的文件标识。
- UI 支持键盘选择端口并建立/删除连接；颜色方案满足基本色弱可辨识要求。
- 相同输入、项目状态和软件版本必须生成确定性的集成页签。

## 13. 验收用例

1. 三个模块各含标量、宏、parameter、二维 packed、unpacked array 和 interface，均可正确展示。
2. TOP input 拉到两个子模块 input，导出为同一行三端连接。
3. TOP output 拉到子模块 input，不报方向错误；现有生成器输出 TOP assign 零。
4. 子模块 output 拉到另一个子模块 input，导出内部连接区。
5. 两个 output 拉入同一普通网络，导出被阻止并显示多驱动 error。
6. 同名端口但位宽不同，只生成 warning 建议，不自动接受。
7. 模板值顺序不同但集合相同，按值正确连接。
8. `data_{{i}}` 不误匹配 `data_debug`。
9. interface 与普通端口拖拽被禁止；相同 interface 类型允许连接。
10. 用户确认 input 未连接，输出后现有生成器将其接零。
11. 源工作簿已有集成页签时，替换前必须确认。
12. 导出文件通过当前生成器 `--check`，且三个 module 页签内容未被修改。
13. 中文路径、中文页签、`module:` 名称和 `修改列`均可处理。
14. 源 XLSX 改动一个端口后重新打开项目，失效连接进入待修复状态。
15. 3000 端口压力用例满足性能目标且画布仍可交互。

## 14. 交付物

- 可离线运行的软件及启动方式。
- 源代码和依赖锁定文件。
- 用户操作说明。
- 架构与数据模型说明。
- 自动化单元测试、集成测试及至少一个端到端 XLSX 样例。
- 打包与发布说明。
- 已知限制和后续路线图。

## 15. 第一版完成定义

只有当以下条件全部满足，第一版才算完成：

- 用户可以从三个 module 页签完成导入、角色选择、自动建议、手工拉线、未连接确认和导出。
- 所有阻断规则在 UI 和导出前校验中一致。
- 导出 XLSX 通过当前项目生成器的 `--check`。
- 验收用例 1～14 自动化或人工记录全部通过；性能用例有可复现报告。
- 不存在会覆盖源文件、丢失已确认连接或静默忽略 error 的已知问题。
