# XLSX 可视化阅读器两轮检视报告

## 结论

`appendix/run_viewer.py` 已完成离线信号阅读器。它能读取现有集成页签或 `.xvlink.json` 工程，使用 TOP 大框、两个子模块小框和带方向箭头的 SVG 信号线展示连接。

## 第一轮：信号模型与交互检视

- XLSX 路径由系统对话框选择，解析使用主项目 `parse_workbook()`，不存在第二套表头/模板规则。
- 从集成页签按连续区和行构建稳定阅读网络；从工程文件保留 UUID 网络和失效端点。
- 信号树按 `TOP ↔ 子模块`、`子模块内部`、`单端/未连接` 分组，支持名称搜索。
- 端点颜色与文字方向标签同时呈现，颜色不是唯一识别方式。
- 选中信号时高亮全部端点、降低其他网络透明度，右侧列出端点、方向、packed/unpacked/interface 形状、分类和扇出。
- SVG 箭头优先从子模块 output 指向其他端点；无可确定 driver 时稳定使用第一端点作为布局起点，不声称功能驱动已被确认。

第一轮审查后将 TOP output 从内部 driver 统计中排除，避免可视化层将 Verilog 模块端口方向误解为网络端功能方向。

## 第二轮：兼容性、离线性与健壮性检视

- `09_version_2` 中的标量、宏、parameter、二维 packed、interface、模板 provenance 都由共享 API 导出到阅读模型：通过。
- 工作簿原始 info/warning/error 不丢失，在诊断面板按级别显示：通过。
- 源指纹改变会告警，工程中不存在的端点仍以占位条目显示，不静默删除：通过。
- HTML/CSS/JS 未引用任何远程 URL；服务拒绝非回环 host，日志不记录查询中的完整文件路径：通过。
- Python `py_compile` 和两个 JavaScript 的 `node --check`：通过。
- 阅读器共享的导出/解析集成测试、中文路径测试和 3000 端口回归：通过。

已知边界：浏览器画布是结构阅读工具，不是 RTL 仿真器；无 output 的网络箭头只表示可视化布局顺序，其真实功能方向必须结合诊断和 XLSX 方向审核。
