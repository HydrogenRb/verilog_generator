# V3.5 跨集成同步与层级信号传播方案

> 本文是方案设计，不代表 V3.5.00 已实现这些写回功能。目标是解决 PRD 14 中“一个模块被多个集成页签引用时要重复修改”和“信号跨多层传递时要逐层手工补端口”的问题。

## 1. 问题本质

当前 XLSX 同时承担两种职责：模块页签是端口定义的事实来源，集成页签又复制了一部分端口引用来描述连接。模块增加端口后，所有引用它的集成页签不会自动出现对应连接行；多层层次中，每一级 TOP 还要手工增加端口并继续向上连接。这不是渲染问题，而是缺少“工作簿级依赖图、稳定对象身份和事务式写回”。

因此不建议在生成 Verilog 时静默补写 XLSX。生成仍应只读；新增独立的“分析 → 预览 → 确认 → 原子写回”流程。

## 2. 推荐数据模型

把整个工作簿解析为一张有向层次图：

```text
ModuleDef ──被例化──> Instance ──属于──> Integration
    │                    │
    └── PortDef          └── PortBinding
                              │
                              └── Net / NA / Constant
```

核心身份不能只依赖显示文字：

- 模块：规范化模块名；
- 实例：`集成页签 + 实例名`；
- 端口：`模块名 + 端口名`；
- 连接：`集成页签 + 实例名 + 端口名`；
- 建议后续在隐藏元数据页保存 UUID，用于承受重命名；没有 UUID 时再回退到以上复合键。

解析完成后建立两类反向索引：

1. `module -> 所有实例位置`，回答“修改这个模块会影响哪些集成页签”；
2. `port/net -> 上下游端点`，回答“这个信号从哪里来、要经过哪些层次”。

## 3. 功能 A：模块端口跨集成同步

用户在模块页新增端口后，执行“同步模块端口”：

1. 找到该模块在全部集成页签中的实例；
2. 对每个实例检查新端口是否已有绑定；
3. 生成候选操作，而不是直接写入：
   - 添加为未连接；
   - input 默认建议 `NA->0`；
   - output 默认建议 `NA` 开路或 `NA->观察名`；
   - 与相邻模块存在同名、同形状端口时建议连接，但不自动确认；
4. 终端展示逐页签 diff，用户可全选或逐项排除；
5. 一次事务写入所有被选页签，写前建立备份，任一写入失败则全部回滚；
6. 重新解析全部集成页签，只有无新增 error 才提交结果。

关键规则：脚本不能只按“同名”自动接线。方向、完整 packed 形状、条件和模板展开值都必须兼容；不确定时只创建待处理项。

难度评估：中高。依赖图本身为中等；保持 XLSX 样式、合并单元格、公式和多个不同布局的安全写回为高难部分。

## 4. 功能 B：一键层级信号传播

提供“传播端口”向导，输入起点、终点和传播方向，例如把底层 `CORE.trace_data`向上拉到`SOC_TOP.trace_data`。

算法：

1. 在实例图上寻找起点模块到目标 TOP 的最短祖先路径；
2. 每经过一级父模块，形成一个变更集：
   - 给父模块页新增透传端口；
   - 在父级集成页添加子实例绑定；
   - 将该父模块的新端口作为下一层的起点；
3. 方向沿路径转换：底层 output 向上仍为父层 output；顶层 input 向下仍为子层 input；inout/interface 必须人工确认；
4. 位宽、数组、条件和模板 provenance 原样传播，禁止只复制最终数值；
5. 名称冲突时给出候选名和影响范围，不静默加 `_2`；
6. 展示整条路径及所有 XLSX 单元格 diff，确认后原子写回并重新全量校验。

若实例图存在多条路径，必须让用户选择实例路径；同一模块在路径中被多个实例复用时，要明确是修改模块公共接口，还是仅为某个层次建立 wrapper。这个选择会改变架构，不能由脚本猜测。

难度评估：高。难点是共享模块的公共接口影响、多路径选择、双向端口、模板展开和跨页签事务，不是简单插行。

## 5. 配套能力建议

| 功能 | 价值 | 难度 |
|---|---|---:|
| 影响分析报告 | 修改前列出受影响页签、实例、端口和生成文件 | 中 |
| 只读层次浏览器 | 按 TOP 展示实例树、网络驱动与负载 | 中 |
| 连接补全建议 | 基于同名、方向和形状给建议，不自动落盘 | 中 |
| 接口 bundle | 把一组经常一起传播的端口定义成逻辑接口组 | 中高 |
| 稳定 UUID 元数据 | 重命名后仍能识别同一模块/实例/端口 | 高 |
| 变更计划文件 | 把预览保存为 JSON，支持代码评审后再应用 | 中 |
| 工作簿 schema 迁移 | 对旧布局先规范化，再启用自动写回 | 高 |

## 6. 安全边界

- 默认只分析，不修改 XLSX；
- 所有写回必须有预览、确认、备份、临时文件和事务回滚；
- 不运行 Excel 公式，不破坏未知 OOXML entry；
- 不确定的方向、位宽、实例路径、重名或多驱动必须阻止自动应用；
- 写回后必须执行全部集成层次解析，而不是只校验当前 TOP；
- 生成 Verilog 与维护 XLSX 分成两个命令，避免普通生成产生隐式源数据变更。

## 7. 分阶段落地

1. 第一阶段（中）：实现只读依赖图和影响报告，不写 XLSX；
2. 第二阶段（中高）：实现“模块新增端口 → 所有引用实例生成变更计划”，输出 JSON/Markdown diff；
3. 第三阶段（高）：实现保样式、事务式 XLSX 应用器；
4. 第四阶段（高）：实现单路径信号逐层传播；
5. 第五阶段（很高）：加入 UUID、重命名迁移、多路径和 wrapper 策略。

推荐先完成前两阶段。它们已经能消除“漏改另一个集成页签”的风险，同时不会过早承担自动写回带来的生产数据破坏风险。
