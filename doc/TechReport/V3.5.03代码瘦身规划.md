# V3.5.03 代码瘦身规划

## 1. 目标与原则

当前主生成器约 6219 行，merger 约 1887 行。多轮迭代后，主生成器同时承担 XLSX 解包、模型解析、兼容修复、连接规划、代码排版、用户段保留、终端菜单和一部分已下线的 XLSX 写回功能。

本规划只识别和安排清理，不修改代码。目标不是单纯减少行数，而是：

1. 删除已经从产品入口移除的功能；
2. 隔离有明确兼容价值但不应继续扩展的 API；
3. 合并重复的宽度/参数决策入口；
4. 降低 `render_integration()`的共享状态和分支耦合；
5. 保留每次删除前可证明的行为基线。

任何清理都不得与紧急功能修复同批进行。先加测试、再删除、最后重构。

## 2. 已明确丢弃的需求

### 2.1 XLSX 变量值扩散

PRD 14 明确要求移除“变量值扩散”。V3.5.03 已经完成入口层移除：

- CLI 不再有 `--spread-value`；
- terminal 菜单不再提供扩散；
- README 将 `define`页签作为批量维护宏匹配值的替代方案。

但实现仍完整保留在主脚本末部，约从 `DiffusionTarget`到 `diffuse_variable_value()`，包括：

- `DiffusionTarget`、`DiffusionResult`；
- `canonical_dimension_symbol()`；
- `iter_editable_module_rows()`、`expanded_factor_targets()`；
- `list_diffusible_variables()`；
- 默认值扩散和范围计算辅助函数；
- worksheet XML 单元格写回；
- XLSX 临时归档、备份和复检；
- 仅为扩散服务的 `inspect_all_integrations()`。

这些函数仍被 V2/V3 历史单元测试直接 import，所以目前属于“公开入口已删除、内部兼容代码未删除”的半下线状态。`shutil`和 `tempfile`在主脚本中也只服务这一子系统；删完后可同步移除这两个 import。`zipfile`和 `ElementTree`仍是 XLSX 读取器所需，不能删除。

建议处理：

1. 把扩散相关历史测试标记为 legacy archive，或迁移到单独的 `legacy_xlsx_diffusion.py`兼容文件；
2. 确认没有外部工具直接 import 这些未文档化函数；
3. 从主生成器删除整个写回子系统和 `inspect_all_integrations()`；
4. 删除只服务扩散的 import；
5. 保留一条测试，确认 CLI 确实拒绝 `--spread-value`，防止功能意外复活。

预计主文件可直接减少约 400 行，并消除“主生成器会不会改源 XLSX”的架构歧义。

## 3. 已替换的历史行为

以下旧需求已经被新规则替换，但当前代码中的残留程度不同。

| 历史行为 | 当前规则 | 残留判断 | 建议 |
|---|---|---|---|
| 生成内部 `reg` | 生成器全部生成 `wire` | 主生成器未发现旧 reg 生成分支；merger 保留 wire/reg 是仍在使用的兼容功能 | 主生成器无需清理；不要误删 merger 的 reg 保留 |
| 普通信号数组放名称右侧 | 全部普通维度放左侧 packed；interface 实例数组例外 | `arrays`字段仍参与解析、形状和 interface 渲染，不是死代码 | 先统一模型再考虑删字段，不能直接删除 |
| 只支持固定 `{{i}}` token | 支持任意命名 token | 当前使用通用模板正则，未发现旧常量分支 | 无清理动作，只保留回归 |
| 单模块未连接区与内部互连区分两套逻辑 | 后续连接区按真实端点数量统一 | 主循环已统一，但 NA、单端、双端仍是必要语义分支 | 不以“分支仍存在”为由删除 |
| 内部 wire 使用 `w_MODULE_signal`或 `_to_`命名 | 以唯一 output 信号为基础生成 `w_signal`，冲突时唯一化 | 未发现旧命名生成分支 | 无清理动作 |
| parameter 默认生成 integer/localparam 混合 | 模块头只用 parameter；内部常量用正文 localparam | 数据模型仍有多类 parameter 字典，但各有当前用途 | 先修正命名歧义，再评估合并字段 |
| 始终生成条件块 | 默认不生成，可由配置开启 | 功能仍有明确配置、渲染和测试，不是已丢弃需求 | 保留；若未来正式废弃需单独 PRD |
| 多集成页签只取固定 TOP | 自动发现并要求选择 | 旧结构识别 fallback 仍用于历史工作簿 | 先定义兼容期限，不能直接删除 |

## 4. 可以立即列入删除候选的死辅助函数

静态引用检查显示：

- `packed_range()`当前无调用；实际渲染使用 `packed_dimension_ranges()`和 `all_packed_dimension_ranges()`。
- `zero_value()`当前无调用；实际零值统一走 `connection_zero_value()` / `connection_constant_value()`。

这两个函数体很小，但删除价值在于避免维护者误选旧入口。删除前应再检查仓库外是否有人直接 import；若脚本只作为 CLI 使用，可在第一阶段直接删除。

以下看似兼容函数不能立即删除：

- `Port.array`仍被历史测试和 review 工具读取；
- `parse_module_label()`仍由模块名回退路径调用；
- `array_range()` / `array_ranges()`仍用于 interface 数组；
- `split_top_level_product(require_spaces=...)`中的参数虽被忽略，但外部调用兼容性未知。

## 5. 兼容层应集中，而不是散落

建议增加一个明确的兼容策略文档或模块，对以下行为给出截止版本：

| 兼容项 | 当前价值 | 清理条件 |
|---|---|---|
| 无“集成_”名称时按结构发现页签 | 支持旧工作簿 | 所有生产工作簿迁移并经过一版 warning 周期 |
| 模块标签旧二元解析入口 | 内部仍使用 | 调用者全部迁移到 details API |
| `Port.array`首维属性 | 历史测试/review 脚本 | 工具改读 `Port.arrays`并公布 API 变更 |
| `require_spaces`忽略参数 | 旧 Python 调用者 | 明确主脚本不再承诺库 API，或完成调用迁移 |
| 单花括号模板自动修复 | 容忍生产表格错误 | 若决定 strict schema，先增加弃用 warning 周期 |
| 空 i/o 自动变 inout | 生产容错 | 只有在输入 schema 强制校验后才能移除 |

兼容逻辑应有稳定的 `W_DEPRECATED_*`诊断和计划删除版本。当前缺少统一弃用机制，导致“正在使用的容错”和“遗留死代码”难以区分。

## 6. 重复决策入口的收敛计划

当前位宽相关入口包括 `Port.shape`、`comparable_port_shape()`、`simple_packed_width()`、`packed_total_width()`、`connection_numeric_width()`、`wire_parameter_map()`和若干连接分支。它们分别回答“声明长什么样”“默认值是否相等”“能否自动 resize”“在 TOP 用哪个符号”，但没有一个统一结果对象。

建议引入只读中间模型：

```text
ResolvedShape
  dimensions          原始逐维表达式
  resolved_dimensions 可选逐维数值
  total_expression    符号总宽
  resolved_total      可选数值总宽
  selected_dimensions bit/index select 后剩余形状
  parameter_sources   每维来源与 override 状态
  resize_policy       direct / warn / flatten / reject
```

然后分三层：

1. 解析层只创建 `Width` / `Port`；
2. 规划层把每个端点转为 `ResolvedShape`并生成 `ConnectionPlan`；
3. 渲染层只把 plan 输出为 wire、assign 和 port binding。

这样可以删除 TOP 路径和内部路径中重复的低位截断/补零判断，并从结构上避免 R-02～R-04 的多维 range-select 问题。

## 7. `render_integration()`拆分建议

该函数超过两千行，建议按数据流拆分，而不是按版本号拆分：

| 新组件 | 职责 | 不应承担 |
|---|---|---|
| `ParameterResolver` | parameter 行、NA parameter、TOP/body 来源映射 | 文本排版 |
| `EndpointResolver` | 精确端口、模板展开、bit/index select、方向校验 | 创建 wire 名 |
| `ConnectionPlanner` | 驱动分析、shape 比较、NA/常量、adapter 计划 | 直接 append Verilog 行 |
| `NameAllocator` | wire、adapter、localparam、genvar 唯一化 | 判断连接语义 |
| `IntegrationRenderer` | 按 plan 对齐并输出文本 | 修改 Module 参数集合 |

重构目标不是立刻减少总代码行，而是使旧分支可证明地删除。第一版拆分必须保持 golden output 不变；只有行为测试稳定后再合并重复逻辑。

## 8. merger 的瘦身边界

merger 的 parser 看起来有重复，但分别处理信号声明、参数、assign、端口、结构行和 USER 段，不能仅凭正则相似就合并。建议：

- 保留计划、备份、暂存、原子替换和回滚层；这些不是冗余。
- 把“模块/实例/行扫描”抽成一次词法扫描，避免各 parser 重复跟踪 module 和 protected region。
- 把 `//USER:`记录统一成稳定 identity，再由不同 handler 匹配。
- 不扩大到任意 SystemVerilog parser；若需求确实扩大，直接评估成熟 parser，避免自研正则继续膨胀。
- `USER_ASSIGN_COMMENT_RE`只是活动 scanner 的兼容别名，确认没有外部 import 后可删除别名并统一名称。

## 9. 分阶段执行计划

### 阶段 0：冻结基线

- 保存当前全量测试结果和关键样例输出摘要；
- 为 R-02～R-06 先添加失败/现状测试；
- 列出所有从 `xlsx2verilog`直接 import 内部函数的仓库内外调用者；
- 约定历史 PRD 只作档案，不再作为当前规格自动回灌。

### 阶段 1：删除明确死代码

- 删除 `packed_range()`、`zero_value()`；
- 删除或隔离变量扩散子系统及相关 import；
- 保留 CLI 拒绝旧参数的测试；
- 目标：主脚本减少约 400 行，无生成结果变化。

### 阶段 2：收口兼容 API

- 迁移 `Port.array`到 `Port.arrays`；
- 消除忽略参数和旧 wrapper；
- 为旧集成页签发现、模板修复、空方向设定弃用策略；
- 每项都经历“warning 一版 -> 删除”的周期。

### 阶段 3：统一宽度和参数规划

- 引入 `ResolvedShape`与 `ConnectionPlan`；
- 先覆盖现有行为，再修复多维适配风险；
- 删除 TOP/内部/NA 各自重复的来源和 resize 判断。

### 阶段 4：拆分文件

建议最终形成：

```text
xlsx2verilog.py          CLI 与兼容入口
xlsx_reader.py           只读 XLSX 解包
schema_parser.py         模块、集成、模板解析
model.py                 Width/Port/Module/Plan
parameter_resolver.py    参数来源
connection_planner.py    方向、驱动、宽度、NA
verilog_renderer.py      纯文本渲染
diagnostics.py           Reporter 与代码表
```

文件拆分不应复制规则。`width`、parameter source 和诊断代码必须各有单一实现来源。

## 10. 删除前验收门槛

每一阶段至少满足：

- `python -m unittest discover -s tests_script -v`通过；
- 主脚本与 merger `py_compile`通过；
- 关键 review workbook 的返回码和诊断代码集合符合基线；
- 生成结果做语义化比较或真实 SystemVerilog compile，而非只比较空格；
- 工作区没有源 XLSX 被修改；
- merger 的 check、备份和回滚测试通过；
- README、功能表和维护指南不再引用已删除入口。

## 11. 不应删除的当前功能

为了避免再次把“默认关闭”误判为“已废弃”，以下当前仍属有效功能：

- `ENABLE_CONDITIONAL_BLOCKS`条件端口；
- `ONLY_TOP`；
- 多集成页签选择；
- define 页签；
- 任意命名模板变量；
- NA、NA->名称、NA->常量和 parameter NA；
- USER CODE 持久化；
- merger 的 wire/reg、localparam/parameter 和 `//USER:`保护；
- interface 与 interface 右侧实例数组例外；
- 旧集成页签结构识别 fallback，除非另行宣布兼容结束。

风险优先级和建议补测见[《V3.5.03 代码风险检视》](V3.5.03代码风险检视.md)。
