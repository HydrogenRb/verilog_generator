## 2. 特殊样例与变量扩散

`review_test_cases/10_special_case/review2case.xlsx` 原件有两类确定冲突：

- `` `APB_1`` 的默认值为 3/4；
- `` `LANE_NUM`` 的默认值为 3/5。

因此原件执行 `--check` 返回码为 2，符合“同名宏不同值报 error”。测试在临时副本上依次扩散 `` `APB_1=4`` 和 `` `LANE_NUM=5`` 后无 error，并生成 4 个 Verilog。交付目录 `review_test_cases/10_special_case/generated/` 来自该临时修复副本，原 XLSX 未因生成动作而改写。

`temp_test/`另提供最小闭环：

- `variable_diffusion_before.xlsx`：`WIDTH` 缺值，返回码 2；
- `variable_diffusion_after.xlsx`：扩散 `WIDTH=(3+5)` 后返回码 0；
- `backup/variable_diffusion_after_20260819_113145_296725.xlsx`：自动备份，与扩散前副本字节一致。

## 5. Python 代码检视

- 安全性：表达式仍使用受限 AST，不调用 `eval()`；XLSX 修改前强制确认和备份；备份重名自动追加序号，避免覆盖历史备份。
- 原子性：Verilog 与 XLSX 都先写同目录临时文件，完整成功后再替换目标。
- 数据隔离：扩散使用物理列坐标写回，但`修改`列通过显式集合隔离；普通解析继续在读取边界移除该列。
- 分层：局部默认值传播、层级传播、generate 指示符、扩散计划和 OOXML 写回均使用独立函数，测试可直接覆盖。
- 向后兼容：保留 `split_top_level_product(..., require_spaces=...)` 形参但忽略旧空格语义，降低外部导入方立即报错的风险。
- 发现并修正的鲁棒性问题：无集成页签的独立模块不共享宏命名空间；漏表头恢复仅接受与端口/方向对同列奇偶的合法模块名，避免把分类列误判成模块块。

未发现会阻止交付的代码问题。当前环境未安装 `ruff`、`mypy`、iverilog 或 Verilator，因此未执行这些外部工具；SystemVerilog 最终 lint/综合仍需在带项目 interface 定义的生产工具链中完成。本轮以 40 项单测、真实工作簿 strict 回归及逐文件独立静态审计作为质量门禁。
