# xlsx2verilog 代码结构与维护指南

## 1. 文档用途

本文面向后续维护该项目的人类开发者和 Agent，说明当前实现的职责边界、数据流、关键不变量、常见修改入口和验证方法。功能格式以 `README.md` 为准；本文重点解释“代码为什么这样组织、修改时要同时检查什么”。

### 2.1 文件顶部功能配置

`xlsx2verilog.py` 的 import 之后、正则常量之前是用户配置区：

```python
VERILOG_FILE_HEADER = """..."""
OVERWRITE_FILE_HEADER = False
ENABLE_CONDITIONAL_BLOCKS = False
ONLY_TOP = False
AUTO_ZERO_FILL_PARAMETER_WIDTH_MISMATCH = False
SHOW_ERROR_MESSAGES = True
SHOW_WARNING_MESSAGES = True
SHOW_INFO_MESSAGES = True
DIAGNOSTIC_VISIBILITY_BY_CODE = {
    "E_DIRECTION": True,
    "W_WIDTH_MISMATCH": True,
    "W_PARAMETER_NOT_EXPORTED": True,
    "W_PARAMETER_AUTO_LOCAL": True,
    "W_PARAMETER_NA_REPAIR": True,
    "I_UNCONNECTED": True,
    "I_ROW_COMMENTED": True,
    # 实际配置表列出所有内建代码
}
```

- `VERILOG_FILE_HEADER`是明文多行头；`OVERWRITE_FILE_HEADER=False`时由`file header` USER 段保护，`True`时重新生成会覆盖该段。
- `ENABLE_CONDITIONAL_BLOCKS=False`是默认生产行为；`True`启用声明、赋零和实例连接的完整条件传播。
- `ONLY_TOP=True`仍解析、校验完整集成层次，但只把选中的 TOP 写入输出目录。
- parameter 维度始终通过数值列比较并输出`W_PARAMETER_WIDTH_MISMATCH`；`AUTO_ZERO_FILL_PARAMETER_WIDTH_MISMATCH=True`时按完整 packed 总位宽自动低位连接和高位补零，默认关闭自动改写。开启后内部网以唯一 output 驱动端形状建线，较宽 input 用`.port({N'b0, w_port})`内联补零，禁止再为该网络生成`assign w_port[高位] = '0`。
- 三个`SHOW_*_MESSAGES`是严重级别总开关；`DIAGNOSTIC_VISIBILITY_BY_CODE`按稳定代码做细粒度过滤。两层都只影响`Reporter.print()`，不删除诊断，也不改变 error/strict 返回码。
- 启动标识常量紧随其后，`main(argv=None)`通过`print_startup_banner()`输出当前版本信息；内部测试调用`main([...])`不会重复输出。
- 这些都是进程级全局配置。测试应使用`unittest.mock.patch`包围一次完整调用。

## 3. 主数据流

```text
CLI / 终端菜单
       │
       ├─ generate()
       │    ├─ XlsxReader.read() ──► Workbook / Sheet
       │    ├─ parse_workbook()
       │    │      ├─ discover_integrations() / find_integration()
       │    │      ├─ parse_define_sheet()
       │    │      ├─ parse_module() ──► Module / Port / Width
       │    │      └─ resolve_hierarchy_defaults()
       │    ├─ render_stub()              非 TOP 模块
       │    ├─ render_integration()       TOP、wire、assign、实例/generate
       │    ├─ preserve_user_code()       合并已有 .v 的受保护用户段
       │    └─ 全部校验通过后原子替换 .v
```

V3.5.03 已从 CLI 和终端菜单移除变量值扩散。源码中暂留的 diffusion 数据类型和辅助函数仅用于历史兼容测试，不属于公开数据流，也不应由新功能调用。

`Reporter`贯穿解析和生成过程。任何 error 都阻止写文件；`--strict` 下 warning 也阻止写文件；info 只记录确定性自动裁决，不改变返回码。输出按 error、warning、info 分组并显示诊断代码，交互式终端分别显示红、黄、青色，非 TTY 不输出 ANSI 控制码。总开关和代码开关只过滤输出，`has_errors/has_warnings`始终检查完整诊断集合。`--check` 完成同样的解析、渲染及已有用户段校验，但不落盘。

## 4. `xlsx2verilog.py` 分层

### 4.1 基础工具与诊断

- `clean()`统一把单元格转换为去除首尾空白的文本。
- `Diagnostic`保存级别、稳定代码与消息。
- `Reporter`负责收集、查询和输出 info/warning/error。`print(stream=None, color=None)`先应用级别总开关，再应用`DIAGNOSTIC_VISIBILITY_BY_CODE`，标题计数只统计真正显示的消息；`color=None`只在目标流为 TTY 时启用颜色。
- 主脚本中的每个`reporter.error/warning/info`调用都必须显式传入已注册的`code=`；`tests_script/test_version3_review1.py`通过 AST 静态检查锁定该约束。外部调用省略代码时分别使用`E_GENERAL/W_GENERAL/I_GENERAL`。新增校验不得在解析中直接`print()`。

### 4.2 OOXML 读取层

- `XlsxReader`直接读取 XLSX ZIP 内的 workbook、relationship、shared string 和 worksheet XML，因此没有 openpyxl 依赖。
- `Sheet.cells`使用 `(row, column)` 的 1-based 坐标保存逻辑单元格；`xml_path`只供 XLSX 写回定位 worksheet part。
- `修改`和`修改列`在 `_read_sheet()` 边界被整列删除并重新映射列号。下游代码不得再次读取或解释这两类列。
- 正常生成调用 `read(..., ignore_review_columns=True)`，因此业务模型完全看不到`修改`列。历史写回辅助逻辑仍可用`False`读取物理坐标，但不是 V3.5 公开入口。
- 普通读取层只保留解析所需的单元格值，不保留样式、图片、公式计算过程或完整合并单元格元数据。

### 4.3 领域模型

| 类型 | 关键字段与含义 |
|---|---|
| `Width` | `kind` 为 literal/macro/parameter，`expression` 用于生成，`default` 用于比较和参数默认值 |
| `Port` | 名称、方向、位宽、位宽维度、XLSX 数组维度、interface、分类、启用功能后的条件宏、模板来源与展开值；普通信号的两类维度最终都渲染在名称左侧 |
| `Module` | 模块名、端口顺序、parameters/macros、宏分类元数据、停用端口/模板/参数、参数渲染表达式/注释，以及显式链接后可由实例覆盖的参数集合 |
| `IntegrationBlock` | 集成页签中一个模块的端口列和方向列；匿名 NA 端点以`anonymous_na=True`表示，不进入模块列表 |
| `InstanceSpec` | 可选元数据表中的模块名、用户实例名、可解析数值次数、原始次数表达式及行号；原始值还可为 TOP parameter 或宏 |
| `Integration` | 集成页签、连续连接区、TOP、去重后的子模块顺序及实例配置 |
| `Wire` | 子模块间内部网络或 NA 占位信号的名称、形状和参数映射；普通内部声明固定为`wire` |
| `Binding` | 一个子模块端口的连接表达式、条件宏，以及是否需要追加人工逻辑 TODO |
| `PortSelection` | V3.5.05 子模块端口最左 packed 维的自然数选择，保存规范化表达式、上下界、宽度和 bit/range 类型 |
| `SlicedInputPiece/Assembly` | 跨多行收集同一实例 input 的目标分段，检查重叠，并在渲染前拼成一个完整端口表达式 |
| `Assignment` | V2 位宽适配及 TOP 命名 NA 观察 assign 的 target/expression、条件传播与可选 TODO |
| `GenerateSpec` | 某个子模块实例的索引变量、各 `[i]` 端点可解析候选范围及可保留的符号范围表达式 |
| `UserCodeRegion` | 一个用户代码段的标签、同标签序号、内容区间和原文，用于安全合并已有 `.v` |
| `DiffusionTarget/Result` | 历史变量扩散辅助模型；V3.5 无 CLI/菜单入口，不得作为当前公开功能依赖 |

`Port.shape`是连接形状比较的统一入口。修改位宽、数组或 interface 规则时，必须同步检查这个属性。

### 4.4 位宽和数组解析

- `evaluate_int_expression()`只允许受控的整数 AST 运算，不执行任意 Python 代码。
- `split_top_level_product()`分隔所有顶层乘号，与空格无关；括号内部的乘号保留为算术。
- `evaluate_int_expression()`默认只接受正整数；显式位宽、数组维度、parameter/宏匹配值及扩散由调用方传入`allow_zero=True`。数字例化次数继续要求大于`0`；V3.3 另外允许合法 TOP parameter 或反引号宏作为不求值的次数表达式，不要把它与维度的“零值保留并告警”语义合并。
- `analyze_width()`识别 literal、反引号 macro、parameter 和可计算表达式。显式维度求值为`0`时保留形状并输出`W_ZERO_WIDTH`；空白位宽配`数值=0`仍是历史兼容标量。
- `analyze_port_dimensions()`同时产生基础 packed width、额外 width dimensions 和 XLSX`数组`dimensions；为保持读取、扩散和附录 API 兼容，模型仍分字段保存它们。
- `port_packed_dimension_ranges()`和`all_packed_dimension_ranges()`把普通信号的 XLSX 数组维度前置到位宽维度之前，统一渲染在名称左侧；`array_ranges()`只为 SystemVerilog interface 实例数组保留。
- `connection_constant_value()`是所有`NA->常量`连接的唯一裁决入口：无尺寸`0/1`把目标端口的数组维度、额外 packed 维度和元素位宽相乘，生成全宽复制式；`8'hFF`等定宽常量解析源宽度，目标更宽时显式高位补零，源更宽或目标不可解析时输出`W_NA_CONSTANT_WIDTH`并保留原文。TOP assign 和子模块 input 绑定必须同时调用该入口，且传入上下文和同一个`Reporter`。

`dimension_defaults()`要求位宽与数值的顶层乘号数量相同。单维乘法默认值必须整体加括号。修改这里时必须覆盖“无空格多维、带空格多维、括号算术、乘号数量不匹配、宏、parameter、数组、interface”。

### 4.5 模板、分类和模块解析

- `normalize_template_text()`兼容并告警单边缺失的模板花括号。
- `template_values_in_row()`从备注单元格提取任意 `{{变量}}` 的花括号列表，也识别`z=0:31`形式的含端点整数范围；支持升序/降序，单个范围受`MAX_TEMPLATE_RANGE_ITEMS`限制。
- `substitute_template_expression()`只把“原始宏 token 内含模板”的宏在完全展开后转成大写，例如`` `Dw_{{i}}``展开为`` `DW_A``；没有模板的`` `log2``、`` `dataWidth``严格保持输入大小写。若模板变量尚未绑定，不得提前大写花括号内的变量名，否则会破坏后续`W_TEMPLATE_BINDING`定位。
- `parse_category()`从分类文本抽取 `条件：MACRO`；剩余文本是显示分类，只写条件时以宏名作为分类。只有 `ENABLE_CONDITIONAL_BLOCKS=True` 时才把宏写入 `Port.condition`。
- `parse_module()`按行继承合并分类、条件和模板取值，执行笛卡尔积展开，并收集端口、宏与 parameter；备注含`*注释*`时先登记对应停用名称，再跳过模型生成；`resolve_module_local_defaults()`随后在同一模块传播无冲突的已知默认值。
- `parameter`分类的`端口名`列是参数名，`数值`是静态匹配默认值；`位宽`为空时直接渲染该值，非空时由`normalize_parameter_expression()`校验为安全单行 Verilog 常量表达式，记录到`parameter_expressions`，并把匹配数值放进`parameter_comments`。表达式允许宏/宏调用、parameter 引用、系统函数、字面量和运算符；生成时 parameter 引用大写，普通宏和系统函数保持拼写，仅模板宏按专用规则大写。两列语义必须分开，不能拿生成表达式做整数位宽计算。
- `macro/macros/宏/宏定义`分类的`端口名`列登记`declared_macros`，`数值`提供静态匹配值；该行不生成 Port、parameter 或活动 define，但参与层次冲突检查和宏参考注释。
- `parse_define_sheet()`识别唯一的`define`页签，以名称和数值表头集中建立宏元数据；`parse_workbook()`在模块解析后把这些值合并进所有参与模块。该页签不进入模块/集成发现，重复宏值冲突仍必须诊断。
- `rebuild_module_symbols()`必须先复制`declared_parameters`、收集参数表达式引用的宏，再收集端口维度引用；否则会丢失显式参数或宏参考。
- 普通信号、端口、模板来源、模板取值、自定义例化名和普通宏严格保留 XLSX 大小写；模块和 parameter 统一大写，模板宏在完全展开后统一大写，默认实例名使用`U_<MODULE>`，输出文件名统一小写。`Port.port_map`、宏表、集成查找和模板 provenance 对齐都必须使用区分大小写的精确值；不要重新引入`.lower()`，因为 Verilog 的`Data`和`data`、`` `log2``和`` `LOG2``都是不同名称。
- `resolve_hierarchy_defaults()`只在同模块或集成页签显式`parameter`链接内传播参数默认值；不得再按同名从 TOP 或兄弟模块隐式继承。宏仍在完整层次内裁决，冲突为 error。最终仍无值的普通符号为 error，模板符号才使用 114 warning。
- 模板连接依赖 `template_source + template_values`，不能改成仅用名称正则匹配，否则 `data_{{i}}` 会误匹配普通端口 `data_debug`。

### 4.6 集成页签识别与连接模型

- `find_integration()`在前 20 行寻找至少两组相邻的`端口名 + i/o`并按空列切分连接区；漏表头块仍可恢复。匿名 NA 列还接受`NA->目标`。`find_instance_specs()`独立扫描可选的`模块名/例化名/例化次数`三列表，并把原始值留给`parse_workbook()`做可定位校验。
- `is_named_integration_sheet()`识别`集成`、`集成_xxx`及兼容的英文名称；`discover_integrations()`按工作簿顺序返回有效候选，优先使用这些命名页签，仅在没有命名候选时退回历史结构识别。
- `parse_workbook(..., integration_sheet=...)`负责统一消歧。单候选自动使用，多候选无选择器时报 error；选中后只解析该层次引用的 TOP/子模块，并跳过所有其他集成页签及无关模块页。
- `inspect_all_integrations()`是历史工作簿级辅助入口，会独立校验每个层次并去重诊断；V3.5 主生成路径不通过它执行源文件写回。
- 第一连续区解释为`TOP ↔ 子模块`；后续多模块区解释为子模块内部网络；后续单模块区解释为未连接端口。
- `parse_module_label_details()`同时拆出模块类型、`*注释*`状态和标签内`例化名:`；兼容入口`parse_module_label()`仍返回旧二元组。`IntegrationChild.key`把模块类型与实例身份分离，同一 module 的多个标签实例必须拥有独立 binding、parameter map、generate 和 USER 段；模块定义仍只生成一次。标签例化名优先于`find_instance_specs()`元数据表。
- `render_integration()`内部的`get_ports()`、`aligned_expansions()`、`validate_sheet_direction()`和`bind()`完成区分大小写的精确端口查找、模板按值对齐、方向校验与条件传播。集成方向空白时使用模块定义并记录 info，不按模块页“空方向=inout”规则处理。
- TOP output 可以连接子模块 input；没有活动 output/inout 驱动的配置由生成器自动置零。TOP input 连接子模块 output 仍是方向错误。
- V2 `aligned_expansions()` 按 provenance 取值并集输出多个对齐行；缺少对端的展开项按未连接处理，数量/集合不同只记录 info。
- `split_index_marker()`识别集成端口末尾 `[i]`。同一子模块的可解析首维范围和符号表达式收集到`GenerateSpec`；显式正整数、TOP parameter 或宏次数优先，没有配置时优先保留一致的符号首维，否则取安全最小数值。显式数字超过范围必须 warning；NA 占位线的新增最左维度必须复用最终次数表达式。
- `split_bit_select()`识别 TOP 引用末尾的常量`[N]`。它只适用于单维 packed 端口，必须检查索引边界；显式表达式直接进入 Binding，不得再被自动低位切片或零扩展覆盖。
- `split_port_selection()`专用于后续子模块内部连接区，识别`[msb:lsb]`、`[base+:width]`和`[bit]`，并统一转换为自然数上下界。`selected_dimensions()`只选择声明最左侧 packed 维，使用数值列/宏值检查边界；符号维按当前匹配值检查并输出`W_PORT_SLICE_WIDTH`，提醒实例覆盖或编译宏变化后重新核对。
- `handle_sliced_internal_row()`只有在同行存在显式范围时接管普通连接路径。一个 output 无论出现多少行，都由`ensure_sliced_output_net()`绑定到同一根完整 wire；每个 input 范围先经`fit_sliced_expression()`按总 bit 数补零或扁平截断，再由`add_sliced_input_piece()`登记。`finalize_sliced_input_assemblies()`按高位到低位拼接，所有未覆盖的最左维元素也生成包含后续维度的全宽 0。不得对 input 端口逐行生成多个 named-port association。
- 显式切片的位宽适配是该语法自身的安全保证，不受`AUTO_ZERO_FILL_PARAMETER_WIDTH_MISMATCH`开关影响。当前不与第一 TOP 连接区、interface、inout、条件端口、模板展开或 generate `[i]`混用；扩展这些组合前必须先定义选择作用于哪个 packed 维，并增加编译级回归。
- `parse_na_connection()`统一解析`NA`、`NA[i]`和`NA->目标`。普通占位声明固定为`wire`；匿名 NA 自动名依次选择端口名、`na_<signal>`和`na_<signal>_r<row>_c<column>`，不得包含模块名或实例名。命名目标必须是合法标识符；与 TOP 端口或已有内部 wire 重名时直接复用、不追加声明，并输出`W_NA_TARGET_CONFLICT`，不再用`E_NA_TARGET`阻止生成。同一命名 NA 重复出现时通过`named_na_wires`复用，不能生成`目标_2`；形状差异记录 warning。该宽松裁决不保证方向、位宽或单驱动正确，warning 文本必须明确要求人工检查。受支持常量经`connection_constant_value()`裁决后绑定 input，output 开路。第一连接区的常量目标只允许驱动 TOP output，并通过`Assignment`生成 assign。全 NA、单端、自动未连接等确定性处理统一记录 info；模块定义页方向列中的 NA 仍表示 interface。
- 子模块互连 wire 以唯一驱动端口命名为`w_<driver_port>`；TOP 位宽 adapter 使用`w_<port>_adapter`。两者都不得加入模块名或实例名；`unique_name()`只在真正冲突时加数字后缀，不能恢复旧的`_to_`拼接。
- `integration_parameter_rows()`按每个连接区的分类列计算继承的参数行并忽略`*注释*`行。普通`NA->A/数字`创建标量正文 localparam；`NA[i]->A`创建`[COUNT][32]` packed localparam，安全解析 i/o assignment pattern，并把实例值设为`A[i]`。只要本行存在 parameter NA，各 parameter/NA 端点的 i/o 都进入初始化来源集合：非空值一致时使用，冲突时精确报错，无显式值时依次使用 TOP parameter 名和子模块数值默认值。元素宽度由文件顶部`PARAMETER_NA_ELEMENT_WIDTH`统一裁决，不能在渲染分支散落魔数。
- `wire_parameter_map()`是 TOP 内部 wire 保留子模块 parameter 表达式的统一入口：macro 直接保留；显式上拉映射到 TOP parameter；未上拉的子模块宽度 parameter 调用`ensure_top_local_parameter()`，用子模块数值默认值创建 TOP 正文 localparam 并同步实例传参。NA、内部互连、空连接零值和位宽适配不得各自再实现一套来源逻辑。
- TOP/子模块形状不同时，先用`packed_total_width()`比较所有 packed 维度的总 bit 数。总数相等时保持直接连接，仅留下形状 warning；不得因`[2][6]`与`[6][2]`的维度顺序不同而创建 adapter。总数不等且子模块 output 更宽时，`flattened_port_width()`必须把 adapter 表达成完整总宽度的一维向量，之后才能调用`low_bits()`；不能对多维信号的单个左侧维度直接做总宽度 part-select。
- 跨层宏冲突诊断从各`Module.macros`收集来源，消息必须包含每个冲突页签及其值，不能只输出无来源的`1/5`。
- `connection_numeric_width()`和`packed_total_width()`使用各维数值列计算完整 packed 总位宽。含 parameter 的形状差异使用`W_PARAMETER_WIDTH_MISMATCH`；配置开启时`fit_source_width(..., sized_zero_fill=True)`对多维 parameter packed 值执行低位截取或`{N'b0, expression}`高位补零。唯一 output 驱动的内部网络优先保持驱动端形状，让每个较宽 input 在 named-port expression 中独立扩展；只有 output/inout 左值不能使用含常量拼接时，才对高位生成等宽`N'b0`赋值。求值为`0`的维度不进入适配计算，避免在“允许保留零位宽”之后继续构造无意义切片。

### 4.7 Verilog 渲染

- `render_macros()`只生成按值列对齐的注释宏参考（``// `define``），不得输出活动宏定义。
- `render_file_header()`生成`file header` USER 段；TOP 的`render_module_header(..., before_module_user=True)`在`module`之前增加`before module`段，stub 不增加；`preserve_user_code()`在`OVERWRITE_FILE_HEADER=True`时只跳过文件头标签的旧内容，其他 USER 段仍必须保留。
- `render_module_header()`对所有进入`module #(...)`的项目统一生成`parameter`，不得生成`localparam`或`integer`；TOP 正文中由 parameter NA/宽度上拉创建的局部常量仍由另一条渲染路径生成`localparam`。宏表达式用匹配值行尾注释。
- packed 范围按维度计算独立列宽：数字和符号表达式均保留为 `[WIDTH -1:0]`，同一维的左方括号固定，表达式紧跟 `[` 从左侧开始，补白插入表达式与 `-1:0]` 之间，因此数字/参数名/宏名左对齐且范围尾部仍固定；所有 `-1:0` 前至少一个空格。XLSX`数组`维度排在最左侧，随后是`位宽`中的多维因子及最终元素宽度，普通端口和内部 wire 的名称右侧不得再生成范围。interface 实例数组是语法例外，只能位于实例名右侧。
- `user_code_block()`在端口声明后生成`before statement`段，并在自动 statement 结束后生成`after statement`段。TOP 的`after statement`必须位于第一个实例 USER 段/实例之前，stub 的该段位于占位 assign 与`endmodule`之间。TOP 还在 module 前生成唯一的`before module`，每个实例块前后另生成`before <MODULE>`和`after <MODULE>`段。
- `connection_zero_value()`和`append_zero_assignment()`统一调用`connection_constant_value("0", ...)`，对全部 packed 维度生成`{A*B{1'b0}}`。只有任一维静态求值为 0 时使用`'0`，避免零次复制；不得让空连接、NA、stub 和 TOP fallback 再次分叉。
- `append_fallback_zero_assignment()`只在所有条件化子模块驱动都不存在时给 TOP output 赋零，避免条件关闭后的悬空，也避免驱动开启时产生多驱动。
- `append_instance_connections()`生成条件化的 named-port association。
- `aligned_binding_expressions()`把 generate 后缀`[i]`拆成独立列，在不破坏右圆括号对齐的前提下对齐索引；NA Binding 的 TODO 必须放在逗号之后，保证 named-port list 语法有效。
- 子模块声明从第 1 列开始；默认实例名是`U_<MODULE>`，可由元数据表覆盖，标签内联例化名优先。显式链接参数与 V3.45 正文局部化的宽度 parameter 进入实例`#(...)`；隐式宽度来源不得被加入 TOP 模块参数列表。port connection 缩进 4 空格并按块对齐右圆括号。
- `integration.commented_child_names`中的实例从 generate/parameter 头到端口列表整体包在`/* XLSX2VERILOG COMMENTED MODULE ... */`中；实例前后 USER 段留在块外，避免嵌套块注释损坏保护协议。
- TOP 只要存在循环实例便统一声明一次`genvar i;`；每个 generate block 的`for`和对应连接表达式都固定使用`i`，generate block 标签仍使用`G_<实例名>`。这些 generate block 顺序出现，不允许嵌套复用同一`i`。
- `parse_user_code_regions()`把标签及其出现序号作为稳定键，校验标记完整、成对且不嵌套；`preserve_user_code()`只替换新模板标记之间的内容。损坏标记或带非空内容的旧段在新结构中失去对应位置必须成为 error。`generate()`先为所有目标完成合并和校验，再开始写任何文件，防止部分覆盖。

### 4.8 已移除的变量值扩散

V3.5.03 不再把`list_diffusible_variables()`、`diffuse_variable_value()`及 XML 写回辅助函数暴露给 CLI 或终端菜单。它们暂留是为了避免一次版本升级同时破坏历史内部测试；新需求不得继续依赖这些入口。集中修改宏的正式替代方案是`define`页签。

### 4.9 独立 merger 的匹配层

- merger 先以新生成文件建立结构模板，再逐层迁移 USER CODE、`wire/reg`、`localparam/parameter`以及`//USER:`整行；每一层替换后重新解析偏移，最后才进入事务写入。
- `PortConnection`同时记录父模块、实例名、端口名、同名端口 occurrence、完整行区间和行号。`parse_port_connections()`必须识别普通`MOD U (...)`、参数化实例的`) U (`以及 generate 内实例。
- `parse_user_owned_lines()`对所有端口连接计数，而不是只给带 USER 标记的行计数。端口匹配先使用`(module, instance, port)`，实例身份不可用时才使用`(module, port, occurrence)`；0 个或多个候选都必须`MergeError`，严禁回退到`candidates[0]`。
- 信号声明按`module + scope(port/body) + signal`优先定位；一行多个 declarator 共享同一关键字替换跨度。多个候选记录带新旧行号 warning，不再用全局`claimed_positions`阻止后续同名项。
- `genvar/generate/endgenerate`的活动行与注释行使用父模块和 occurrence 作为结构键整行保护。
- `AUTO_OPEN_BCOMPARE=True`只在 Linux 的实际写入路径异步启动`BCOMPARE_COMMAND`；左侧取本轮备份旧文件，右侧取生产结果。自动对比不得参与合并成功判定。

以下逻辑仅在 `ENABLE_CONDITIONAL_BLOCKS=True` 时出现：当子模块每个端口都有 `ifdef` 时，没有可作为逗号锚点的无条件首端口。`append_instance_connections()`因此使用 `XLSX2VERILOG_INTERNAL_HAVE_CONNECTION_<MODULE>`临时预处理标记：第一个活动连接不加逗号，后续活动连接前加逗号；标记在每个实例前清理并在实例后再次清理。修改这段代码必须验证零个、一个、多个活动端口以及多个条件同时开启。默认关闭时 `Binding.conditions`为空，不进入这条渲染路径。

## 5. 条件端口必须保持的联动

启用 `ENABLE_CONDITIONAL_BLOCKS`后，一个 `Port.condition`不能只影响端口声明，还必须同步影响以下位置：

1. 模块端口声明及分类块。
2. 桩模块 output 的默认赋零。
3. 子模块实例的 named-port association。
4. 引用条件化 TOP 端口的连接表达式。
5. 条件化子模块 output/inout 对 TOP output 的备用置零逻辑。

任何一处遗漏都会产生“预处理后引用不存在端口”“逗号残留”或“某个配置下信号悬空”。相关核心回归位于：

- `test_techreview3_groups_conditions_and_local_alignment`
- `test_conditional_blocks_are_disabled_by_default`
- `test_every_child_port_can_be_conditionally_compiled`
- `test_conditional_child_driver_gets_zero_fallback_when_disabled`

## 6. CLI 与交互层

- `main()`是统一入口；显式参数和终端 GUI 最终都回到这里。
- `build_parser()`定义`--output`、`--check`、`--strict`、`--list`和多集成消歧用的`--integration SHEET`；V3.5 不再注册`--spread-value`。
- 无参数且 stdin/stdout 都是 TTY 时进入 `interactive_main()`。
- `read_terminal_key()`分别处理 Windows 和 POSIX 原始按键。
- `arrow_menu()`通过注入 `key_reader`和`output`实现无真实终端单元测试。
- `choose_integration_sheet()`只在发现多个有效候选时调用菜单；单个`集成`或`集成_xxx`直接返回页签名。菜单展示页签名与 TOP 名，Esc 回到上级菜单。

新增只读/生成类 CLI 选项时应保证非交互流水线兼容，不应强制等待用户输入。多集成 CLI 未传`--integration`时必须明确失败而不能静默选择第一个。当前主生成器没有任何修改源 XLSX 的公开命令。

## 8. 错误处理与安全不变量

- 输入文件不是有效 XLSX、引用模块缺失、非法端口名、确定的方向冲突等必须成为 error。
- 不确定位宽、位宽差异、索引越界和多驱动风险通常为 warning；自动 localparam、模板子集和所有未连接处理为 info。
- 不得在存在 error 时写出部分结果。
- 已有 `.v` 中的用户代码段必须在全部目标写入前完成解析和合并；标记损坏、嵌套、标签不配对或非空旧段无新位置时宁可拒绝生成，也不能丢弃代码。
- Verilog 生成路径不得覆盖源 XLSX。V3.5 主生成器没有源 XLSX 写回入口。
- 输出先写同目录 `.tmp`，成功后再替换目标 `.v`。
- 不得通过 `eval()`执行位宽表达式。
- 不得把用户工作簿中的文本直接变成跨行 Verilog 注释或未校验标识符。
- 不要删除或回滚与任务无关的 `source/`、XLSX 或其他用户工作区修改。
- merger 以新生成结构为真源，只按稳定键迁移人工决策；实例端口优先按实例身份定位，occurrence 只作兼容回退。USER 行缺键或实例端口精确键仍多义时必须在写入前失败，不能选择候选列表第一项；普通声明等同目标重复则按 V3.5 契约 warning 后由旧文件后一条覆盖。
- merger 的默认持久备份必须锚定新生成路径的同级目录，不能写入生产目标；执行仍需同目录暂存、原子替换和失败回滚。
- merger 的目录目标由`_recursive_target_index()`按 casefold 文件名递归索引，但只收集新代码源实际涉及的文件名；相关目标重名必须列出冲突路径并终止，无关文件重名必须忽略。
- `DEFAULT_TARGET_PROJECT`只是 CLI 第二位置参数的显式默认值；未配置时省略目标必须失败，不能从当前目录或源码位置猜测生产项目。
- 非 check CLI 必须在任何备份/写入前逐项调用确认；N 项不进入事务。`MergeResult.changed`只记录实际确认项，结尾打印文件名和绝对路径。

## 10. 拆分代码的建议

当前单文件便于直接分发，但继续增长时可按以下边界拆分，行为必须先由现有测试锁定：

- `xlsx_reader.py`：OOXML 与逻辑 Sheet。
- `model.py`：Width、Port、Module、Integration、Diagnostic。
- `parser.py`：位宽、模板、module、integration 和层级默认值传播。
- `verilog_renderer.py`：header、stub、integration、用户代码段合并和条件预处理渲染。
- `xlsx_editor.py`：历史变量发现、扩散规则、备份和 worksheet 原子写回设计；V3.5 已移除公开入口。
- `cli.py`：argparse、终端菜单和修改确认。

拆分时不要复制规则；尤其是位宽、模板和条件逻辑必须保持唯一实现来源。
