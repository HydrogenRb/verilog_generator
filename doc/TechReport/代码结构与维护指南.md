# xlsx2verilog 代码结构与维护指南

## 1. 文档用途

本文面向后续维护该项目的人类开发者和 Agent，说明当前实现的职责边界、数据流、关键不变量、常见修改入口和验证方法。功能格式以 `README.md` 为准；本文重点解释“代码为什么这样组织、修改时要同时检查什么”。

### 2.1 文件顶部功能配置

`xlsx2verilog.py` 的 import 之后、正则常量之前是用户配置区。目前只有：

```python
ENABLE_CONDITIONAL_BLOCKS = False
```

- `False`是默认生产行为：分类中的`条件：MACRO`仍会被整理成分类名，但 `Port.condition`设为 `None`，后续所有渲染均为无条件内容，输出不会包含该功能产生的预处理条件块。
- `True`启用完整条件传播：声明、桩模块赋零、TOP 备用赋零和实例连接均遵守条件宏。
- 这是进程级全局配置。不要在解析一个工作簿的中途改变它；测试需要使用 `unittest.mock.patch`在一次完整的 `generate()`调用外层临时开启。

## 3. 主数据流

```text
CLI / 终端菜单
       │
       ├─ generate()
       │    ├─ XlsxReader.read() ──► Workbook / Sheet
       │    ├─ parse_workbook()
       │    │      ├─ discover_integrations() / find_integration()
       │    │      ├─ parse_module() ──► Module / Port / Width
       │    │      └─ resolve_hierarchy_defaults()
       │    ├─ render_stub()              非 TOP 模块
       │    ├─ render_integration()       TOP、wire、assign、实例/generate
       │    ├─ preserve_user_code()       合并已有 .v 的受保护用户段
       │    └─ 全部校验通过后原子替换 .v
       │
       └─ diffuse_variable_value()
            ├─ 预检查 / 变量发现 / 写回计划
            ├─ y/n 安全门槛 ──► backup/时间戳副本
            └─ worksheet XML 临时 ZIP 后原子替换 XLSX
```

`Reporter`贯穿解析和生成过程。任何 error 都阻止写文件；`--strict` 下 warning 也阻止写文件；info 只记录确定性自动裁决，不改变返回码。输出按 error、warning、info 分组，交互式终端分别显示红、黄、青色，非 TTY 不输出 ANSI 控制码。`--check` 完成同样的解析、渲染及已有用户段校验，但不落盘。

## 4. `xlsx2verilog.py` 分层

### 4.1 基础工具与诊断

- `clean()`统一把单元格转换为去除首尾空白的文本。
- `Diagnostic`保存级别与消息。
- `Reporter`负责收集、查询和输出 info/warning/error。`print(stream=None, color=None)`按严重程度分组；`color=None`只在目标流为 TTY 时启用颜色，测试可显式传入布尔值。新增校验应写入 `Reporter`，不要在解析中直接 `print()`。

### 4.2 OOXML 读取层

- `XlsxReader`直接读取 XLSX ZIP 内的 workbook、relationship、shared string 和 worksheet XML，因此没有 openpyxl 依赖。
- `Sheet.cells`使用 `(row, column)` 的 1-based 坐标保存逻辑单元格；`xml_path`只供 XLSX 写回定位 worksheet part。
- `修改`和`修改列`在 `_read_sheet()` 边界被整列删除并重新映射列号。下游代码不得再次读取或解释这两类列。
- 正常解析调用 `read(..., ignore_review_columns=True)`；变量扩散以 `False` 读取物理坐标，但通过 `Sheet.ignored_columns`保证后续发现和模板范围扫描仍不接触`修改`列。
- 普通读取层只保留解析所需的单元格值，不保留样式、图片、公式计算过程或完整合并单元格元数据。扩散写回只改目标 `<c>` 为 inline string，ZIP 中其他 entry 原样复制。

### 4.3 领域模型

| 类型 | 关键字段与含义 |
|---|---|
| `Width` | `kind` 为 literal/macro/parameter，`expression` 用于生成，`default` 用于比较和参数默认值 |
| `Port` | 名称、方向、位宽、packed/unpacked 维度、interface、分类、启用功能后的条件宏、模板来源与展开值 |
| `Module` | 模块名、端口顺序、parameters、macros、分类行产生的`declared_parameters`；`port_map`用于精确查找 |
| `IntegrationBlock` | 集成页签中一个模块的端口列和方向列；匿名 NA 端点以`anonymous_na=True`表示，不进入模块列表 |
| `Integration` | 集成页签、连续连接区、TOP 和去重后的子模块顺序 |
| `Wire` | 子模块间内部网络或 NA 占位信号的名称、形状、`wire/reg`类型和参数映射 |
| `Binding` | 一个子模块端口的连接表达式、条件宏，以及是否需要追加人工逻辑 TODO |
| `Assignment` | V2 位宽适配的 target/expression 与条件传播 |
| `GenerateSpec` | 某个子模块实例的索引变量，以及各 `[i]` 端点可解析的候选范围 |
| `UserCodeRegion` | 一个用户代码段的标签、同标签序号、内容区间和原文，用于安全合并已有 `.v` |
| `DiffusionTarget/Result` | 一次可选宏/parameter 与扩散操作的备份、修改数、前后诊断 |

`Port.shape`是连接形状比较的统一入口。修改位宽、数组或 interface 规则时，必须同步检查这个属性。

### 4.4 位宽和数组解析

- `evaluate_int_expression()`只允许受控的整数 AST 运算，不执行任意 Python 代码。
- `split_top_level_product()`分隔所有顶层乘号，与空格无关；括号内部的乘号保留为算术。
- `analyze_width()`识别 literal、反引号 macro、parameter 和可计算表达式。
- `analyze_port_dimensions()`同时产生基础 packed width、额外 packed dimensions 和端口名后的 unpacked arrays。
- `width_expression()`到`array_ranges()`负责把模型转换为 Verilog 范围，并应用子模块参数到 TOP parameter 的映射。

`dimension_defaults()`要求位宽与数值的顶层乘号数量相同。单维乘法默认值必须整体加括号。修改这里时必须覆盖“无空格多维、带空格多维、括号算术、乘号数量不匹配、宏、parameter、数组、interface”。

### 4.5 模板、分类和模块解析

- `normalize_template_text()`兼容并告警单边缺失的模板花括号。
- `template_values_in_row()`从备注单元格提取任意 `{{变量}}` 的花括号列表，也识别`z=0:31`形式的含端点整数范围；支持升序/降序，单个范围受`MAX_TEMPLATE_RANGE_ITEMS`限制。
- `parse_category()`从分类文本抽取 `条件：MACRO`；剩余文本是显示分类，只写条件时以宏名作为分类。只有 `ENABLE_CONDITIONAL_BLOCKS=True` 时才把宏写入 `Port.condition`。
- `parse_module()`按行继承合并分类、条件和模板取值，执行笛卡尔积展开，并收集端口、宏与 parameter；`resolve_module_local_defaults()`随后在同一模块传播无冲突的已知默认值。
- `parameter`/`parameters`/`参数`/`参数定义`分类由`is_parameter_category()`识别。该分类的`端口名`列实际是 parameter 名，`数值`列是默认值；这些行进入`Module.declared_parameters`而不创建`Port`。`normalized_parameter_default()`接受安全整数或完整反引号宏并规范宏名大小写；模板展开、合法标识符和重复冲突仍在`parse_module()`内完成。
- `rebuild_module_symbols()`必须先复制`declared_parameters`再收集端口维度引用，否则后续默认值传播会意外丢失显式 parameter。
- 普通信号、端口、模板来源和模板取值严格保留 XLSX 大小写；模块、实例、宏和 parameter 仍统一大写，输出文件名统一小写。`Port.port_map`、集成查找和模板 provenance 对齐都必须使用区分大小写的精确值；不要重新引入`.lower()`，因为 Verilog 的`Data`和`data`是两个合法且不同的信号。
- `resolve_hierarchy_defaults()`在全部模块读取完之后将 TOP 已知值传播给下层空值。上下层 parameter 不同由实例覆盖；任何跨模块宏冲突都是 error。最终仍无值的普通符号为 error，模板符号才使用 114 warning。
- 模板连接依赖 `template_source + template_values`，不能改成仅用名称正则匹配，否则 `data_{{i}}` 会误匹配普通端口 `data_debug`。

### 4.6 集成页签识别与连接模型

- `find_integration()`在前 20 行寻找至少两组相邻的`端口名 + i/o`，并按空列切分连接区；后续已有模块名及端口数据但漏掉重复表头的块也会恢复。紧跟正常列对、模块名与表头均为空、且所有非空值均为`NA`/`N/A`或`NA[索引]`的列会被识别为匿名 NA 端点；`IntegrationBlock.anonymous_na`用于阻止它进入模块解析和实例列表。
- `is_named_integration_sheet()`识别`集成`、`集成_xxx`及兼容的英文名称；`discover_integrations()`按工作簿顺序返回有效候选，优先使用这些命名页签，仅在没有命名候选时退回历史结构识别。
- `parse_workbook(..., integration_sheet=...)`负责统一消歧。单候选自动使用，多候选无选择器时报 error；选中后只解析该层次引用的 TOP/子模块，并跳过所有其他集成页签及无关模块页。
- `inspect_all_integrations()`供变量扩散这种工作簿级操作使用，会独立校验每个层次并去重诊断，避免多页签选择歧义阻断安全预检查。
- 第一连续区解释为`TOP ↔ 子模块`；后续多模块区解释为子模块内部网络；后续单模块区解释为未连接端口。
- `module_name_above_header()`同时接受直接模块名、`module:`和`module：`前缀。
- `render_integration()`内部的`get_ports()`、`aligned_expansions()`、`validate_sheet_direction()`和`bind()`完成区分大小写的精确端口查找、模板按值对齐、方向校验与条件传播。集成方向空白时使用模块定义并记录 info，不按模块页“空方向=inout”规则处理。
- TOP output 可以连接子模块 input；没有活动 output/inout 驱动的配置由生成器自动置零。TOP input 连接子模块 output 仍是方向错误。
- V2 `aligned_expansions()` 按 provenance 取值并集输出多个对齐行；缺少对端的展开项按未连接处理，数量/集合不同只记录 info。
- `split_index_marker()`识别集成端口末尾 `[i]`。同一子模块的可解析首维范围收集到 `GenerateSpec`，生成时取安全最小值；没有可解析值时 warning 并使用 1。
- `split_bit_select()`识别 TOP 引用末尾的常量`[N]`。它只适用于单维 packed 端口，必须检查索引边界；显式表达式直接进入 Binding，不得再被自动低位切片或零扩展覆盖。
- 内部多模块区使用`NA`/`N/A`表示待补逻辑端；该端既可使用普通模块列，也可使用无模块名、无表头的匿名 NA 列。唯一真实端口为 input 时创建`reg`，为 output/inout 时创建`wire`，绑定上设置`requires_todo`。`NA[i]`还会把索引注册到真实端模块的`GenerateSpec`，并在占位信号最前方增加与安全循环次数一致的 unpacked 维，使`.port(placeholder[i])`仍保持端口完整形状。第一连接区应先把所有子模块列引用拆成真实端口与 NA 两类；TOP 引用存在而对端为 NA 时只保留 TOP 观察端口，不能调用`get_ports(child, "NA", ...)`，无真实驱动的 output 交给统一置零流程处理。全 NA 行应告警；模块定义页方向列中的 NA 仍表示 interface，不要混用两条规则。
- 子模块互连 wire 以唯一驱动端口命名为`w_<driver_port>`；`unique_name()`只在冲突时加数字后缀，不能恢复旧的`_to_`拼接。
- parameter 先提升到 TOP，实例统一传递 TOP 名称；任一维是 parameter 时跳过定宽差异诊断与切片。宏在层次内必须同值，冲突为 error。
- 跨层宏冲突诊断从各`Module.macros`收集来源，消息必须包含每个冲突页签及其值，不能只输出无来源的`1/5`。
- `simple_packed_width()`、`fit_source_width()` 和 `adapter_assignments` 只在可确定的单维 fixed/macro 端口上创建低位切片/高位补零；内部 wire 宽度取数字最大值。

### 4.7 Verilog 渲染

- `render_macros()`生成直接且按值列对齐的 `` `define``。
- `render_module_header()`生成 parameter、分类注释和 ANSI 端口声明；功能开关启用时再生成条件端口。普通端口与 interface 名称共用对齐列。input/output 继续显式生成`wire`，inout 只生成`inout [range] name`，不得重新添加`wire`。
- packed 范围按维度计算独立列宽：数字和符号表达式均保留为 `[WIDTH -1:0]`，同一维的左方括号固定，表达式紧跟 `[` 从左侧开始，补白插入表达式与 `-1:0]` 之间，因此数字/参数名/宏名左对齐且范围尾部仍固定；所有 `-1:0` 前至少一个空格。第二维及更多维度重复同一算法，缺少后续维度的信号保留空列以维持名称对齐。端口名后的 unpacked 范围继续使用独立的右对齐字段。
- `user_code_block()`在端口声明后生成`before statement`段；TOP 的每个实例块前后另生成`before <MODULE>`和`after <MODULE>`段。`render_stub()`随后为非 TOP 模块生成占位 output 赋零；stub 和 TOP 都直接在最后一条主体内容后生成 `endmodule`。
- `append_zero_assignment()`区分标量/packed 向量和 unpacked array；模块级 `assign` 默认从第 1 列开始，数组使用 generate-for 逐元素赋零且循环内部继续按层级缩进。
- `append_fallback_zero_assignment()`只在所有条件化子模块驱动都不存在时给 TOP output 赋零，避免条件关闭后的悬空，也避免驱动开启时产生多驱动。
- `append_instance_connections()`生成条件化的 named-port association。
- `aligned_binding_expressions()`把 generate 后缀`[i]`拆成独立列，在不破坏右圆括号对齐的前提下对齐索引；NA Binding 的 TODO 必须放在逗号之后，保证 named-port list 语法有效。
- 子模块声明和实例名从第 1 列开始，实例名是 `U_<MODULE>`；parameter connection 和 port connection 缩进 4 空格，分别计算最长表达式并在表达式右侧补空格，使每个连接块的右圆括号对齐；不要跨不同实例强求全局列宽。
- 数组置零和实例循环都先输出独立`genvar`声明，再输出`generate`与不含`genvar`关键字的`for`。同一 TOP 多个循环复用相同索引名时只声明一次。输出路径使用`module.name.lower()`，模块声明本身继续大写。
- `parse_user_code_regions()`把标签及其出现序号作为稳定键，校验标记完整、成对且不嵌套；`preserve_user_code()`只替换新模板标记之间的内容。损坏标记或带非空内容的旧段在新结构中失去对应位置必须成为 error。`generate()`先为所有目标完成合并和校验，再开始写任何文件，防止部分覆盖。

### 4.8 XLSX 变量值扩散

- `list_diffusible_variables()`从模块页的位宽/数组字段及显式 parameter 分类发现规范化后的宏和 parameter。
- `iter_editable_module_rows()`同时返回当前行是否属于 parameter 分类；显式 parameter 名从`端口名`列发现，扩散时其`数值`单元格必须与所有位宽引用一同更新。
- `spread_default_cell()`负责单维覆盖、多维对应因子覆盖、空因子数字/114 补全，以及模板的`范围是{...}`列表。
- `normalize_diffusion_value()`只接受正自然数或整体带括号且安全可计算的表达式。
- `diffuse_variable_value()`先运行完整预检查和写回计划，再要求确认；`n`必须保持文件字节不变且不得建备份，`y`先`copy2`到`backup/`再调用`write_xlsx_cell_updates()`。
- `write_xlsx_cell_updates()`仅重写发生改变的 worksheet XML part，并通过同目录临时 ZIP 原子替换。不得把它改成解压整个工作簿后覆盖，也不得在备份成功前修改源文件。

以下逻辑仅在 `ENABLE_CONDITIONAL_BLOCKS=True` 时出现：当子模块每个端口都有 `ifdef` 时，没有可作为逗号锚点的无条件首端口。`append_instance_connections()`因此使用 `XLSX2VERILOG_INTERNAL_HAVE_CONNECTION_<MODULE>`临时预处理标记：第一个活动连接不加逗号，后续活动连接前加逗号；标记在每个实例前清理并在实例后再次清理。修改这段代码必须验证零个、一个、多个活动端口以及多个条件同时开启。默认关闭时 `Binding.conditions`为空，不进入这条渲染路径。

## 5. 条件端口必须保持的联动

启用 `ENABLE_CONDITIONAL_BLOCKS`后，一个 `Port.condition`不能只影响端口声明，还必须同步影响以下位置：

1. 模块端口声明及分类块。
2. 桩模块 output 的默认赋零。
3. 子模块实例的 named-port association。
4. 引用条件化 TOP 端口的连接表达式。
5. 条件化子模块 output/inout 对 TOP output 的备用置零逻辑。

任何一处遗漏都会产生“预处理后引用不存在端口”“逗号残留”或“某个配置下信号悬空”。相关核心回归位于：

- `test_techreview3_groups_conditions_and_local_alignment`
- `test_conditional_blocks_are_disabled_by_default`
- `test_every_child_port_can_be_conditionally_compiled`
- `test_conditional_child_driver_gets_zero_fallback_when_disabled`

## 6. CLI 与交互层

- `main()`是统一入口；显式参数和终端 GUI 最终都回到这里。
- `build_parser()`定义`--output`、`--check`、`--strict`、`--list`、多集成消歧用的`--integration SHEET`和一次处理一个变量的`--spread-value VARIABLE VALUE`。
- 无参数且 stdin/stdout 都是 TTY 时进入 `interactive_main()`。
- `read_terminal_key()`分别处理 Windows 和 POSIX 原始按键。
- `arrow_menu()`通过注入 `key_reader`和`output`实现无真实终端单元测试。
- `choose_integration_sheet()`只在发现多个有效候选时调用菜单；单个`集成`或`集成_xxx`直接返回页签名。菜单展示页签名与 TOP 名，Esc 回到上级菜单。

新增只读/生成类 CLI 选项时应保证非交互流水线兼容，不应强制等待用户输入。多集成 CLI 未传`--integration`时必须明确失败而不能静默选择第一个。`--spread-value`会原地修改数据，因此按 PRD 特意保留不可绕过的 `y/n` 人工确认。

## 8. 错误处理与安全不变量

- 输入文件不是有效 XLSX、引用模块缺失、非法端口名、确定的方向冲突等必须成为 error。
- 不确定位宽、位宽差异和多驱动风险通常为 warning；确定性的参数上提、模板子集和自动未连接处理为 info。
- 不得在存在 error 时写出部分结果。
- 已有 `.v` 中的用户代码段必须在全部目标写入前完成解析和合并；标记损坏、嵌套、标签不配对或非空旧段无新位置时宁可拒绝生成，也不能丢弃代码。
- Verilog 生成路径不得覆盖源 XLSX。只有用户明确进入变量值扩散且输入 `y` 后才允许原地更新；此前必须建立时间戳备份。
- 输出先写同目录 `.tmp`，成功后再替换目标 `.v`。
- 不得通过 `eval()`执行位宽表达式。
- 不得把用户工作簿中的文本直接变成跨行 Verilog 注释或未校验标识符。
- 不要删除或回滚与任务无关的 `source/`、XLSX 或其他用户工作区修改。

`review_test_cases\09_version_2\test.xlsx --check`和`review_test_cases\10_special_case\review2case.xlsx --check`应返回 2，因为原件刻意保留同名宏冲突。相关测试在临时副本上逐项扩散后检查生成结果、低位连接和 generate，不得为了让命令返回 0 而修改原始样例。

## 10. 拆分代码的建议

当前单文件便于直接分发，但继续增长时可按以下边界拆分，行为必须先由现有测试锁定：

- `xlsx_reader.py`：OOXML 与逻辑 Sheet。
- `model.py`：Width、Port、Module、Integration、Diagnostic。
- `parser.py`：位宽、模板、module、integration 和层级默认值传播。
- `verilog_renderer.py`：header、stub、integration、用户代码段合并和条件预处理渲染。
- `xlsx_editor.py`：变量发现、扩散规则、备份和 worksheet 原子写回。
- `cli.py`：argparse、终端菜单和修改确认。

拆分时不要复制规则；尤其是位宽、模板和条件逻辑必须保持唯一实现来源。
