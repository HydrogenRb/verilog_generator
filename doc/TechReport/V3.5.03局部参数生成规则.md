# V3.5.03 parameter / localparam 生成规则

本文总结 `xlsx2verilog.py` 当前实际生成的两类参数，并重点说明 TOP 正文 `localparam` 的触发条件、命名、取值和实例映射。本文是行为审计，不修改脚本。

## 1. 先区分两种参数

| 类型 | 生成位置 | 关键字 | 外部能否覆盖 |
|---|---|---|---|
| 模块参数 | `module NAME #(...)` | `parameter` | 能 |
| 集成局部参数 | TOP 的 `module`正文、内部 wire 之前 | `localparam` | 不能 |

当前脚本不会在 `module #(...)`中生成 `localparam`，也不会生成 `integer`参数。两类参数在代码模型中分别存入 `Module.parameters`和 `integration_local_parameters`。

## 2. 模块页 parameter 分类

模块页分类为 `parameter`、`parameters`、`参数`或`参数定义`时，该行声明模块参数，不是端口。

- 参数名转为大写；模板参数名可展开。
- “数值”是静态匹配默认值，允许 `0`。
- “位宽”留空时，生成值取“数值”。
- “位宽”非空时，它被当成 parameter 表达式；支持宏、宏调用、其他 parameter、系统函数、常量和受限运算符。
- 表达式中的 parameter 标识符转为大写；宏和系统函数保持用户输入大小写。
- “数值”仍保留为静态比较依据和行尾注释，不求值 parameter 表达式。

例如：

```text
parameter | para_a | `LANE_NUM     | 4
parameter | para_b | para_a+1      | 5
parameter | DW     | `log2(para_b) | 3
```

生成：

```systemverilog
module EXAMPLE #(
parameter PARA_A = `LANE_NUM,    // 4
parameter PARA_B = PARA_A+1,     // 5
parameter DW     = `log2(PARA_B) // 3
)(
...
);
```

## 3. TOP 正文 localparam 的生成位置

只要 `integration_local_parameters`非空，TOP 在 `before statement` USER 段之后、内部 wire 之前生成：

```systemverilog
// Integration-local parameters for NA and child-owned widths.
// parameter NA 及子模块位宽上拉创建的 TOP 语句区局部参数。
localparam NAME = value;
```

有维度的 parameter NA 数组会生成：

```systemverilog
localparam [COUNT -1:0][32 -1:0] NAME = initializer;
```

其中元素宽度由文件顶部 `PARAMETER_NA_ELEMENT_WIDTH`控制，当前为 32。

## 4. 会创建正文 localparam 的场景

### 4.1 `parameter NA->名称`

集成 parameter 行包含一个非 TOP 的 NA 端点和至少一个子模块 parameter 时：

```text
子模块.P  <->  NA->A
```

生成 `localparam A = value;`，并在实例中生成 `.P(A)`。

值的优先级：

1. NA 端点 `i/o`或同一行 parameter 端点 `i/o`中的一致非空值；
2. 同一行唯一 TOP parameter 的名称；
3. 无来源时使用占位值 `114`。

多个非空初始化来源内容不同会产生 `E_PARAMETER`。TOP parameter 与 parameter NA 可以同时出现；没有显式 `i/o`值时，TOP parameter 名就是 initializer，不再因“同时使用”而报错。

### 4.2 `parameter NA->数字`

例如 `NA->514`。数字被解释为 localparam 的值，localparam 名取第一个子模块 parameter 名：

```systemverilog
localparam CHILD_PARAM = 514;
```

若同一行还提供其他 initializer 来源，脚本记录 info 并以 `NA->数字`为准。

### 4.3 `parameter NA[i]->名称`

该形式同时驱动参数数组和 generate：

```systemverilog
localparam [COUNT -1:0][32 -1:0] B = '{...};
...
.P(B[i])
```

- COUNT 优先取该子模块显式例化次数；找不到时告警并使用 1。
- `{1,2}`会规范为 SystemVerilog assignment pattern `'{1,2}`。
- 单值会成为 `'{default: value}`。
- 逗号列表中的空项会被忽略并产生 `W_PARAMETER_NA_REPAIR`。
- COUNT 可静态求值时，位置元素数必须一致；不可求值时无法在生成期检查元素数。
- 同一子模块 parameter NA 行不能混用不同 generate 索引名。

### 4.4 未显式链接的子模块宽度 parameter

当子模块端口的宽度 parameter 被带到 TOP 内部 wire、NA、generate 或其他集成表达式，而集成页没有明确链接它时，`ensure_top_local_parameter()`会：

1. 读取子模块“数值”默认值；
2. 在 TOP 正文创建同名 localparam，冲突时生成唯一名称；
3. 把子模块实例参数映射到该 localparam；
4. 让 TOP 内部 wire 的维度使用这个名称；
5. 输出 `W_PARAMETER_AUTO_LOCAL`和 `I_PARAMETER_LINK`。

例如：

```systemverilog
localparam DW = 8;
wire [DW -1:0] w_data;
CHILD #(.DW(DW)) U_CHILD (...);
```

若 TOP 已有同名且默认值相同的模块参数，则直接复用 TOP parameter，不再创建正文 localparam。这是名称和值相同即视为同一来源的当前规则。

### 4.5 集成 parameter 行直接给子模块数字

子模块 parameter 的集成 `i/o`填写自然数时：

- 实例参数仍直接连接数字，例如 `.DW(8)`；
- 若该 parameter 参与 TOP 内部 wire 宽度，脚本另外创建 `localparam DW = 8;`供声明使用。

直接写反引号宏时，实例和内部宽度均可直接使用宏，通常不创建正文 localparam。

当前“直接值”语法只接受非负整数或单个反引号宏，不接受 `A+1`、`` `F(A)``等通用表达式。这与模块页 parameter 表达式的语法范围不同。

### 4.6 TOP 数字 parameter 向子模块传递

若 TOP parameter 在集成 `i/o`中直接指定数字并传给子模块：

- 子模块实例取得这个数字；
- 子模块宽度在 TOP 正文需要符号时，可能再创建以子模块 parameter 名命名的 localparam。

若 TOP parameter 本身作为符号来源链接，实例通常使用 TOP parameter 名，不需要另建正文 localparam；个别名称不同且来源是纯数字默认值的宽度映射仍会生成局部别名。

## 5. 显式 parameter 互连的特殊现状

没有 NA、没有直接 `i/o`覆盖时，集成 parameter 行用于显式链接：

- 行内有 TOP parameter：它是源，子模块实例映射到该 TOP parameter。
- 行内没有 TOP parameter，只有两个或更多子模块 parameter：代码调用 `add_top_local_parameter()`提升第一个子模块参数。

第二种情况存在实现与命名不一致：函数名和 info 文本说“localparam”，但函数实际把条目写入 `top.parameters`，最终生成在 `module #(...)`中，关键字是可覆盖的 `parameter`，不是 TOP 正文 `localparam`。

例如当前实际结果是：

```systemverilog
module TOP #(
parameter P_A = 8
)(...);
```

而不是：

```systemverilog
module TOP (...);
localparam P_A = 8;
```

历史测试 `test_child_parameter_link_creates_top_localparam`的名字也沿用了旧称，但断言实际检查的是 TOP module parameter。该歧义已列入代码风险 R-06，本轮没有修改。

## 6. 命名、复用和冲突

`add_integration_local_parameter()`执行以下规则：

| 情况 | 结果 |
|---|---|
| 合法名称 | 强制大写 |
| 名称非法 | 报 `E_NA_TARGET`，内部选备用名，但 error 会阻止写入 |
| 与 TOP module parameter 重名 | 改为 `LOCAL_NA_<NAME>`，必要时追加序号 |
| 与已有正文 localparam 同名、值和维度都相同 | 复用同一个名称 |
| 同名但值或维度不同 | 改为 `LOCAL_NA_<NAME>`并唯一化 |
| 未链接子模块宽度同名冲突 | 通常尝试 `<MODULE>_<NAME>`再唯一化 |

名称分配依赖解析和遇到顺序。调整工作簿行顺序、增加同名项或增加 TOP parameter 后，唯一化后缀可能改变；merger 或人工代码不应把自动后缀当成跨版本永久 API。

## 7. 默认值、表达式与数值匹配的关系

需要区分三个概念：

| 概念 | 用途 |
|---|---|
| parameter 生成表达式 | 实际写入 Verilog，例如 `` `log2(PARA_B)`` |
| “数值”匹配值 | 生成期比较形状、估算总位宽、输出注释 |
| 实例 override | `.P(...)`在特定子模块实例上的最终来源 |

生成器不会完整模拟 Verilog elaboration。位宽比较和自动适配主要使用 XLSX“数值”，不一定反映下游对 TOP parameter 的再次 override。`AUTO_ZERO_FILL_PARAMETER_WIDTH_MISMATCH=True`时尤其需要注意，因为生成器可能把默认差值固化为定宽补零和 part-select。

## 8. 主要边界

- `NA[i]`的元素宽度固定为 32，超过 32 bit 的 initializer 可能被上下文截断。
- assignment pattern 和 packed parameter 数组依赖 SystemVerilog。
- COUNT 不可求值时无法验证 initializer 列表长度。
- 参数名统一大写，可能与用户原本区分大小写的名称发生语义变化或冲突。
- 正文 localparam 的唯一化依赖工作簿顺序。
- 直接 parameter `i/o`的语法比模块页 parameter 表达式窄。
- “显式子模块参数互连但无 TOP 端点”当前创建 module parameter，而不是正文 localparam。

## 9. 使用建议

1. 需要外部配置的值明确放在 TOP 模块页 parameter 分类中。
2. 只服务内部连线的值使用 parameter NA 或允许脚本自动创建正文 localparam。
3. 不要依靠相同名称自动推断业务等价性；关键参数应在集成页显式链接。
4. parameter NA 数组超过 32 bit 时，先调整 `PARAMETER_NA_ELEMENT_WIDTH`并补充编译测试。
5. 打开 parameter 位宽自动适配前，验证所有可能的实例 override，而不只验证 XLSX 默认值。

相关位宽行为见[《V3.5.03 位宽行为矩阵》](V3.5.03位宽行为矩阵.md)，实现歧义和建议修改见[《V3.5.03 代码风险检视》](V3.5.03代码风险检视.md)。
