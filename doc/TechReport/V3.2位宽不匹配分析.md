# V3.2 位宽不匹配分析

本文说明`xlsx2verilog.py`如何得到连接形状、何时自动适配、何时只诊断，以及为什么零位宽和 parameter 不进入固定切片。可执行样例位于[`review_test_cases/17_v3_techreview2_width_boundary`](../../review_test_cases/17_v3_techreview2_width_boundary/检视报告.md)。

## 1. 宽度信息的来源

一个普通端口的完整 packed 形状依次由以下三部分组成：

1. `数组`列的所有顶层维度；
2. `位宽`列中最终一维之前的顶层`*`维度；
3. `位宽`的最终元素宽度。

例如`数组=DEPTH`、`位宽=LANES*DW`的完整形状是`[DEPTH][LANES][DW]`，静态总位宽是三者默认值的乘积。数字直接提供数值；宏使用同名宏在当前层次裁决后的匹配值；parameter 保留给 SystemVerilog elaboration。`数值`列用于比较，不会替换生成代码里的宏或 parameter 表达式。

## 2. 裁决矩阵

| 场景 | 是否 warning | 生成行为 | 设计理由 |
|---|---:|---|---|
| 形状完全一致 | 否 | 直接连接 | 不引入多余逻辑 |
| TOP 源 8 bit → 子模块 input 4 bit | `W_WIDTH_MISMATCH` | 子模块连接低 4 bit | 截断高位必须可见且可审查 |
| TOP 源 4 bit → 子模块 input 8 bit | `W_WIDTH_MISMATCH` | 高 4 bit 补 0 | 不依赖隐式无符号扩展 |
| 子模块 output 4 bit → TOP 8 bit | `W_WIDTH_MISMATCH` | 建 4 bit 适配 wire，TOP 高位补 0 | 明确未驱动高位 |
| 子模块 output 8 bit → TOP 4 bit | `W_WIDTH_MISMATCH` | TOP 只取低 4 bit | 明确丢弃高位 |
| 内部 output 3 bit → input 5 bit | `W_WIDTH_MISMATCH` | 内部 wire 取 5 bit，驱动端未覆盖高 2 bit 补 0 | 一根网络服务所有端点 |
| 内部 output 9 bit → input 2 bit | `W_WIDTH_MISMATCH` | 内部 wire 取 9 bit，input 接低 2 bit | 保留驱动端完整信号 |
| 一个内部网络有多个不同固定宽度端点 | 每个相对驱动端不同的端点一条 warning | wire 取可解析最大宽度，各 input 分别截断/扩展 | 防止连接顺序影响结果 |
| 显式`signal[0]` | 否 | 原样连接该 bit | Excel 已明确表达用户意图，优先于自动适配 |
| 任一维是 parameter | 否 | 不固定切片或补零 | parameter 可能在实例 elaboration 时被覆盖 |
| 宏两端默认值不同 | error | 禁止写文件 | 同一层次同名宏不能同时代表两个宽度 |
| 多维 packed 形状不同 | `W_WIDTH_MISMATCH` | 保留原形状直接连接，不自动扁平/重排 | 维度次序可能具有协议语义，不能只按总 bit 数猜测 |
| interface 类型不同或 interface/普通信号混接 | error | 禁止不安全连接 | interface 不是普通 bit vector |
| 显式零位宽 | `W_ZERO_WIDTH` | 保留`[0 -1:0]`，不参与适配 | 保留原始规格，同时避免构造负数切片或最大宽度网络 |
| `NA->0`或`NA->1` | 否 | 按全部 packed 维度乘积生成复制式 | 保证每一 bit 都得到目标值 |
| `NA->8'hFF`→16 bit | 否 | `{{8{1'b0}}, 8'hFF}` | 显式高位补零 |
| `NA->8'hFF`→4 bit | `W_NA_CONSTANT_WIDTH` | 保留`8'hFF`，由 Verilog 上下文截断 | 不静默掩盖高位丢失 |
| `NA->8'hFF`→不可静态解析目标 | `W_NA_CONSTANT_WIDTH` | 保留原常量 | 不猜测 parameter 或未知宏的 elaboration 结果 |

## 3. 为什么 parameter 不比较

假设子模块声明`parameter DW = 8`，实例又通过`#(.DW(TOP_DW))`覆盖。Excel 中的`8`只是默认匹配值，并不是最终物理宽度。如果生成器提前按 8 bit 切片，实例把`DW`覆盖为 16 后，生成代码反而会永久丢失高位。因此，只要连接形状的任一维属于 parameter，固定宽度比较和自动 adapter 都跳过，由 elaboration 使用最终参数值解析。

宏不同：同一编译层次的一个宏名只有一个预处理值。两个模块都使用`` `DW``却分别填写 8 和 16，无法通过连接 adapter 消除定义冲突，所以脚本报 error，并要求先统一 Excel。

## 4. 零位宽的边界

Verilog/SystemVerilog没有跨仿真器、综合器都一致的零宽 net 声明。V3.2 接受`0`的含义是“生成器不因边界配置中断，并把问题带到可审查输出”，而不是保证`[0 -1:0]`可综合。为避免级联错误：

- 显式`0`、`(1-1)`、默认值为 0 的宏/parameter 和数组维度都会产生`W_ZERO_WIDTH`；
- 生成文本保留对应表达式；
- 零值不进入低位截断、高位补零或内部 wire 最大宽度计算；
- `--strict`仍会阻止带此 warning 的发布结果。

推荐在 CI 中先用普通`--check`收集所有零宽配置，再用`--strict`作为最终发布门禁。项目如果用“功能关闭时宽度为 0”的惯例，应在 USER CODE、上层生成系统或项目专用预处理条件中处理，不要假定所有 RTL 工具对`[0 -1:0]`行为相同。

## 5. 第 17 组样例的预期结果

运行：

```powershell
python .\xlsx2verilog.py .\review_test_cases\17_v3_techreview2_width_boundary\width_boundary.xlsx --check
```

预期返回码为`0`，产生：

- `W_ZERO_WIDTH`：1 条；
- `W_WIDTH_MISMATCH`：8 条；
- `W_NA_CONSTANT_WIDTH`：1 条；
- error：0 条。

因此同一文件使用`--strict`时预期返回`2`。这不是回归失败，而是样例有意覆盖 warning 边界。生成目录中的 4 个`.v`文件用于人工检视截断、补零、内部 wire、NA 常量和零宽声明。
