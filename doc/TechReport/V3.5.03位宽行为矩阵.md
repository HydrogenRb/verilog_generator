# V3.5.03 位宽行为矩阵

本文记录 `xlsx2verilog.py` 在 V3.5.03 的实际行为，不是新需求，也不代表本轮修改了生成逻辑。结论来自代码路径复核、现有单元测试，以及 `review_test_cases/17_v3_techreview2_width_boundary/width_boundary.xlsx` 的只读回归。

## 1. 术语与内部模型

普通信号的完整 packed 形状按以下顺序组成：

```text
数组列的各维度 -> 位宽列除最后一项外的各维度 -> 位宽列最后一项
```

生成时这些维度全部位于信号名左侧。例如：

```text
数组=DEPTH，数组数值=4
位宽=LANE*DW，数值=2*8
```

生成：

```systemverilog
wire [DEPTH -1:0][LANE -1:0][DW -1:0] signal;
```

标量 `1` 是例外：若它是唯一的最终元素位宽，不生成 `[1 -1:0]`。若 `1` 是显式的外层维度，仍生成 `[1 -1:0]`。

本文中的“形状”表示逐维比较结果，例如 `[2][6]` 与 `[6][2]` 形状不同；“总位宽”表示各维数值乘积，两者均为 12 bit。

## 2. 输入解析矩阵

| XLSX 写法 | 内部类型 | 数值来源 | 生成表达式 | 边界行为 |
|---|---|---|---|---|
| 位宽空白 | literal | 空白或可计算的正整数“数值” | 默认为标量 `1` | 空白位宽配“数值=0”仍回退为标量 1 |
| `1`、`8`、`0` | literal | 位宽自身 | 标量、`[8 -1:0]`、`[0 -1:0]` | `0`保留并报 `W_ZERO_WIDTH` |
| `(2+3*4)` | literal | 安全整数求值 | `[14 -1:0]` | 只接受受限算术，不执行名称或函数 |
| `` `DATA_W`` | macro | “数值”列，或同层次已知宏值 | ``[`DATA_W -1:0]`` | 无法解析时可能使用 114 占位并 warning；不生成活动 `` `define`` |
| `DATA_W` | parameter | “数值”列 | `[DATA_W -1:0]` | 名称转为大写，并进入参数来源处理 |
| `A*B` | 两个 packed 维度 | “数值”也必须有两个顶层因子 | `[A -1:0][B -1:0]` | `*`两边空格无意义 |
| `(A*B)` | 单维表达式 | 需要可计算默认值 | 解析成功后固化为 literal 宽度 | 括号阻止顶层维度拆分 |
| interface modport | interface | 不使用普通位宽 | `type.modport name` | 不参与普通 wire 的宽度适配 |

“位宽”和“数值”的顶层 `*` 因子数量必须一致。数组列与数组数值列执行同一规则。表达式不能安全求值时，部分路径会报错，允许不确定值的模板路径会 warning 并使用 `114`。

## 3. 声明方向与语法

| 模块页方向 | 普通声明 | 未连接时 |
|---|---|---|
| input | `input wire ...` | 在集成实例端接完整形状的 0 |
| output | `output wire ...` | stub 中对整信号赋 0；集成端可开路或由 TOP 兜底 |
| inout | `inout ...` | 不附加 `wire`；通常开路 |
| 空白 | 按 `inout` 生成并附 TODO | 同 inout，同时有 `W_IO_DEFAULTED` |
| interface | `type.modport name` | 不生成普通连续赋值适配 |

所有普通内部网络、NA 占位和 adapter 都声明为 `wire`。多维 packed 与 interface 使用 SystemVerilog 语法，即使输出扩展名仍为 `.v`，工具链也必须启用 SystemVerilog 模式。

## 4. 形状判断与诊断

连接比较会尝试把每一维解析为数值：

- literal 使用自身值；
- macro 使用层次中收集到的匹配值，找不到时退回该维的默认值；
- parameter 使用 XLSX“数值”列形成的默认值；
- 任一维仍不可解析时，退回符号形状比较。

逐维结果不同即形成形状 mismatch：

- 任一端含 parameter：`W_PARAMETER_WIDTH_MISMATCH`；
- 其他普通信号：`W_WIDTH_MISMATCH`。

warning 表示“形状不同”，不等于一定生成 adapter。后续还会判断连接区域、方向、开关、是否可计算总位宽以及是否有显式选择。

## 5. 第一连接区：TOP 与子模块

### 5.1 方向裁决

| TOP 方向 | 子模块方向 | 实际处理 |
|---|---|---|
| input | input | TOP 是源，子模块是接收端；可在子模块端口表达式中截断/补零 |
| output | input | 允许；TOP 信号向子模块输入扇出。若没有子模块驱动 TOP，TOP 后续被置 0 |
| output/inout | output | 子模块驱动 TOP；必要时使用切片、补零 assign 或 adapter wire |
| input | output | `E_DIRECTION`，整次生成停止写入 |
| 任意 | inout | 可以直接绑定，但当前自动 resize 分支不覆盖 child inout |

集成页签方向还会先与模块页方向核对。集成方向空白时继承模块定义，不按模块页“空方向变 inout”的方式重新推断。

### 5.2 自然数和可解析宏的一维信号

该类信号不依赖 `AUTO_ZERO_FILL_PARAMETER_WIDTH_MISMATCH`：

| 源与目标 | 行为 |
|---|---|
| 等宽 | 直接连接 |
| 源宽、目标窄 | 目标连接源的低位，单 bit 使用 `[0]` |
| 源窄、目标宽，目标为 input | 端口表达式高位补 0 |
| 窄 child output 驱动宽 TOP output | child 连接 TOP 低位，并对 TOP 高位另行 assign 0 |
| 宽 child output 驱动窄 TOP output | child 先连接 adapter，TOP 取 adapter 低位 |

### 5.3 parameter 维度

默认 `AUTO_ZERO_FILL_PARAMETER_WIDTH_MISMATCH=False`：始终保留形状 warning，但不根据“数值”列自动改写连接。

设为 `True`：脚本把所有 packed 维度的匹配值相乘，按总 bit 数进行低位连接和高位补零。补零使用定宽形式，例如：

```systemverilog
.data_in({4'b0, w_data_out})
```

需要注意：适配数值来自 XLSX 默认/匹配值，不是 Verilog elaboration 后的最终参数值。生产环境若会覆盖 parameter，参见风险检视文档 R-01。

### 5.4 多维信号

- 形状不同但可解析总位宽相等，例如 `[2][6]` 对 `[6][2]`：保留 warning，直接连接，不创建 adapter。
- child output 与 TOP output 总位宽确实不同：当前代码把 child output adapter 声明为一维扁平向量后再切低位，避免直接在某个子维度上访问总位宽范围。
- TOP 作为 rvalue 驱动 child input 时没有同等完整的“先扁平化”保护；开关打开且总宽不同时存在越界风险，见 R-02。
- `[2][6]` 与 `[6][2]` 的直接 packed 赋值是按总 bit 序传递，不是矩阵转置。维度语义不同的设计仍需人工转换。

### 5.5 显式选择

- 显式 bit select（如 `sig[3]`）视为用户明确指定的连接，不再进行 mismatch 自动适配。
- generate/index 标记（如 `sig[i]`）用于数组实例连接。当前宽度计算仍可能参考完整端口形状，复杂的多维索引加自动适配需要额外验证，见 R-03。

## 6. 后续连接区：子模块内部互连

后续连接区先找驱动端，再创建一根内部 wire：

| 场景 | 行为 |
|---|---|
| 恰好一个 output | 以该 output 为语义驱动源 |
| 没有 output | `W_DRIVER_RISK`，创建 wire 并赋完整形状 0 |
| 多个 output | `E_DRIVER_CONFLICT`，阻止写入 |
| 全部 interface | 直接建立 interface 网络，不做普通位宽适配 |
| interface 与普通端口混连 | `E_INTERFACE_CONNECTION` |

一维自然数或可解析宏不一致时，wire 取最大宽度，窄端连接低位，唯一窄 output 未覆盖的高位另行补 0。

parameter 参与时：

- 开关关闭：warning 后保持驱动端形状和直接连接；
- 开关打开且各端总宽可解析：wire 保持唯一 output 的形状，各 input 在端口表达式内按总宽截断或定宽补 0；
- 多维参数网络的截断目前可能直接对多维 wire 使用总位宽 part-select，存在越界风险，见 R-04。

纯 literal/macro 的多维连接目前不会进入一维 resize 算法；形状不一致通常只 warning 并保持连接。这与 parameter 多维在开关开启后的处理并不完全对称。

驱动识别只把 `output`计为驱动，`inout`不计入。这可能令含 inout 的网络被判断为“无 output 驱动”并追加置零，见 R-05。

## 7. NA、未连接与常量的宽度

`NA->0`、`NA->1`和自动未连接 input 使用目标完整 packed 形状：

```systemverilog
// 目标为 [A][B]
{A*B{1'b0}}
{A*B{1'b1}}
```

若任一维静态为 0，则改用 `'0`，避免生成零次复制。定宽常量行为如下：

| 常量与目标总宽 | 行为 |
|---|---|
| 常量较窄 | 显式高位补 0 |
| 等宽 | 原样连接 |
| 常量较宽 | `W_NA_CONSTANT_WIDTH`，保留常量，由 Verilog 上下文截断 |
| 目标总宽不可解析 | 保留常量并 warning，不猜测 |

这里的总宽同样来自 XLSX 匹配值。`NA->名称`只决定观察/占位 wire 的名称，不消除形状、方向或多驱动风险。

## 8. 零位宽

显式 `0` 会保留为 `[0 -1:0]`并产生 `W_ZERO_WIDTH`，不参与切片和自动适配。该策略保留了 XLSX 规格，但 SystemVerilog 工具对零位宽的解释不具可移植性，warning 不能在量产流程中忽略。

空白位宽配“数值=0”与显式位宽 `0` 不同：前者由于历史兼容会成为标量 1，后者才是零位宽。这是容易误解的边界。

## 9. 当前安全边界总结

| 类型 | 一维 | 多维、总宽相等 | 多维、总宽不等 |
|---|---|---|---|
| literal / 可解析 macro | 自动低位适配 | warning 后直接连接 | 多数内部路径只 warning；TOP child-output 路径可扁平 adapter |
| parameter，开关关闭 | warning 后直连 | warning 后直连 | warning 后直连 |
| parameter，开关打开 | 按匹配值适配 | warning 后直连 | 部分路径适配；TOP rvalue 和内部网络仍有多维切片风险 |
| interface | 不做普通适配 | 直接连接同类 interface | 普通/interface 混连报错 |
| 显式 bit select | 视作用户裁决 | 不适用 | 不自动适配 |

因此生产默认保持 `AUTO_ZERO_FILL_PARAMETER_WIDTH_MISMATCH=False`是较保守的选择。开启前应至少增加“参数覆盖后 elaboration”“多维 TOP input 截断”“多维内部网络截断”“indexed 多维连接”四类编译回归。
