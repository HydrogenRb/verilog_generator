# Real Test 2：Ibex Core 两级嵌套例化

## 开源项目依据

- 项目：lowRISC Ibex，Apache-2.0。
- 固定版本：`7b5df75a041affe56e8c235260f98a09b3319008`。
- [`ibex_core.sv`](https://github.com/lowRISC/ibex/blob/7b5df75a041affe56e8c235260f98a09b3319008/rtl/ibex_core.sv) 直接例化 `ibex_if_stage`、`ibex_id_stage` 和 `ibex_load_store_unit`。
- [`ibex_if_stage.sv`](https://github.com/lowRISC/ibex/blob/7b5df75a041affe56e8c235260f98a09b3319008/rtl/ibex_if_stage.sv) 下继续例化预取缓冲、压缩指令解码器和可选 dummy-instruction 模块。
- [`ibex_prefetch_buffer.sv`](https://github.com/lowRISC/ibex/blob/7b5df75a041affe56e8c235260f98a09b3319008/rtl/ibex_prefetch_buffer.sv) 还会继续例化 [`ibex_fetch_fifo`](https://github.com/lowRISC/ibex/blob/7b5df75a041affe56e8c235260f98a09b3319008/rtl/ibex_fetch_fifo.sv)，用于判断更深层级时的扩展方式。

## 为什么有两个 XLSX

当前脚本一次只接受一个集成页签，因此一个工作簿只能生成一个集成层级。为保持生成器不变，本案例采用分层工作簿：

1. [`01_core_layer.xlsx`](./01_core_layer.xlsx)：生成 `ibex_core → ibex_if_stage + ibex_id_stage + ibex_load_store_unit`。
2. [`02_if_stage_layer.xlsx`](./02_if_stage_layer.xlsx)：生成 `ibex_if_stage → ibex_prefetch_buffer + ibex_compressed_decoder + ibex_dummy_instr`。

第一层输出在 [`layer_core_generated`](./layer_core_generated)，第二层输出在 [`layer_if_generated`](./layer_if_generated)。最终将第二层的集成版 `ibex_if_stage.v` 替换第一层同名桩文件，得到 [`composed_generated`](./composed_generated)。

组合后的层级为：

```text
ibex_core
├── ibex_if_stage
│   ├── ibex_prefetch_buffer
│   ├── ibex_compressed_decoder
│   └── ibex_dummy_instr
├── ibex_id_stage
└── ibex_load_store_unit
```

## 能力边界

1. 单个 XLSX 不能同时表达两个集成层级；必须分层生成并在外部组合。这是本轮最直接的层级能力边界。
2. 如果继续还原真实的 `ibex_prefetch_buffer → ibex_fetch_fifo`，需要第三个工作簿并再次替换桩文件；层级越深，人工组合步骤越多。
3. 外部组合依赖上下层工作簿对同名模块接口保持完全一致。脚本不会跨工作簿自动检查；本次由独立审计确认一致。
4. `ibex_core` 的真实端口和内部连接包含 package 类型、数组、PMP、CSR、RVFI、ALU、写回与条件配置。本案例只抽取 IF/ID/LSU 的纯标量/向量连接切片。
5. 生成结果能证明层级、连接、位宽、tie-off/open 规则可扩展到真实命名和较多端口，但仍缺少真实组合/时序逻辑，不能替换 Ibex RTL。

分类结论：分层生成和人工组合可以构造两级层次，结构审计通过；“单工作簿单集成层”和“只生成连接骨架”是当前边界，未修改生成器。
